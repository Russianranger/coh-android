The old whole-cache API is unchanged. New `coh_wr_trick_detach` consumes a qualified opaque old Trick owner only on final success and copies the exact contiguous 767,172-byte count/length-prefixed Trick suffix at source offset 12,769,880. It never reencodes records or borrows old views. Whole cache SHA256 remains cf9595e54bc65a40d2dddc3a5a13c475d7c2ce07a96420e6001b0e2312926bc1; the retained suffix SHA256 is e82e825340e7abb16ccb3d34a756a991b73eeab33bc291021a608822620c65a5. Each row/name/source/child offset is translated into owned bytes, preserving original order, fields and source association/age. Whole input and copied suffix digests are independently required before publication.

Admission reuses the frozen opaque source proof, independently acquires exact path/historical generation, checks whole-source identity, parses every copied row and compares original admitted name/source-file/age/child counts, builds a bounded sorted index and preserves highest-ordinal duplicate ownership. New getter/decoder code is generated by a narrow checked mechanical transformation of frozen reader slices; original source tables/private types/numeric projection remain identical. Views require detached-owner lifetime only. The report retains the original admission report explicitly as historical provenance, separately from new owned/preparation bytes.

The old source remains valid on every failure; candidate pins/allocations roll back on digest, allocation, cancellation, source identity or budget failure. Success retires the staging loader pin and old source owner. **TexOpt and other independent owners still pin the whole body.** Memory savings require separately retiring all those owners and trimming/destroying their cache loader. The test demonstrates no saving while TexOpt remains, then actual loader resident bytes become zero and allocated bytes return to the post-mount empty baseline after it retires and trim runs; detached views work even after loader/provider destruction. This is not a detached full TexOpt owner or permission to remove needed material inputs.

A configured 16 MiB loader total is sufficient for this exact 13,537,052-byte cache; the former fixture's 32 MiB reservation was not an API minimum. Whole loader reservations, existing source metadata/static reserve and every other owner/provider/runtime peak are explicitly charged. Preparation reserves a further new whole loader, detached metadata+suffix and32 KiB own stack/control/static before acquisition/allocation; same physical loader reservations are conservatively double charged. Existing view/control stack plus original provider caches are caller external-budget prerequisites. No cap is raised. Prepare dictionaries before unrelated GEO/graph resource peaks where possible; this module does not assert process RSS or close system/runtime allocator overhead.

It verifies exact byte equality to the source suffix, source-only flags, ownership transfer/rollback, tiny budgets before acquisition, allocation and both digest failures, operation-boundary cancellation, wrong generation/corrupt whole source, aliases, and post-cache-retirement use.
