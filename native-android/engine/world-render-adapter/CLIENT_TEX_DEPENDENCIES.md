# Immutable historical texture dependency staging

`coh_wr_tex_dependencies` joins the opaque retained cached-header subset with the exact historical native TexOpt cache/Surface owner. It atomically takes ownership of the input-header owner on success, retains independently owned matching TexOpt records, and exposes native immutable Basic parameter and texture dependency observations. It is usable input to a future renderer material supplier; it is not an admitted live BasicTexture/composite table or material.

## Implemented source-owned portion

For each exact header, the module uses the source-derived header directory and Basic key already qualified by `coh_wr_tex_inputs`. Current admission explicitly requires the original header name to end in `.dds`. Source `texFixName` executes its safe explicit `.dds` branch; other formats refuse. Initial Basic flags start zero, receive the source DDS bit, then the exact retained `texFillInBind` alpha/fade, bump and named cubemap statements. Cached header TexOpt flags are never copied wholesale into Basic flags.

The original `texResetTrickBasedParametersBasic` body runs unchanged with an owner-local callback to a prepared immutable historical lookup. Its query is the exact source `dirname + '/' + Basic name`, including directory inheritance and name-derived flags; it is not the raw cached filename or only a basename. The callback reads the retained postprocessed record and never mutates it. Gloss, Surface, replaceable and reload checks follow original source. The source target/load-state/reset statements from `texSetBindsSubBasic` are executed exactly: cube-map versus2D target, clamp flags, both NOT_LOADED states and hasBeenComposited0. The following `texWordFind` call is NOT replaced with a fake empty result: dynamic TexWord selection remains explicitly unresolved.

The original initial composite factory copies only dirname/name and self `orig_bind`; actual material fields are filled later by `texSetBindsSubComposite`. The adapter therefore exposes initial name/directory identity only and does not allocate/publish a TexBind or self-pointer permission. Source enumeration order is unproven; imported-header key collisions already refuse rather than inventing first-owner/overlay order.

All13 stored postprocessed blend names and three enabled fallback names remain inspectable. Original `IsValidTexName` decides which requests participate in source availability checks. The original strict `texFixName` is used only within its qualified bounded domain (one leading! removed, fewer than128 bytes, no unsafe bare4..7-byte suffix). Unsafe cases such as bare `white` are explicitly UNQUALIFIED_KEY; the separate corrected-source guarded policy is not silently enabled. Local searches target ONLY the imported-header subset and report PRESENT_IMPORTED_HEADER or NOT_OBSERVED. Neither outcome proves active namespace selection, asset generation or a complete factory availability result. Source fallback/default textures are never synthesized.

## Ownership and budget

The source-header owner transfers only after all entries, postprocessing, accounting and final cancellation succeed. Failure retires candidate TexOpt records and preserves both source and output pointers. The loader must outlive the dependency owner. Cache and Surface owners are needed only during preparation; retained TexOpt strings survive their retirement. Returned views borrow the dependency owner and its transferred header body pins.

The aggregate contract charges the full source-header owner/whole loader reservation, native cache owner/whole loader reservation, Surface owner/static data and external old/runtime/provider/code peaks. Shared loader reservations may be conservatively counted twice. Before allocation it adds the entry-array allocation plus64KiB covering this module's preparation/control and the nested lookup/postprocess/static reservations. Every retained record adds its owned bytes before another record is prepared. Budget/overflow/cancellation failures are atomic. This is component accounting, not a measured whole-process cap. Caller output memory must be disjoint/writable and outside all borrowed blobs.
