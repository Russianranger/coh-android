# Fixed seven default-source inspection and optional retention

This adds a thin staging adapter and C inspection driver around existing asset/header modules. It adds no texture selection, namespace, codec, material or renderer algorithm. No real .31 staging or authentic default body has yet been inspected. The checked-in qualification uses controlled layout and body pins explicitly labeled as such. Its source_revision is the pre-tranche baseline; the recorded source_sha256 entries bind the exact new source bytes independently of that label.

Actual CLI after the separately qualified .31 staging helper completes:

```sh
python native-android/engine/world-render-adapter/inspect_default_headers.py \
  --staging-root /absolute/exact/control-output \
  --payloads /absolute/the/same/prepared/payloads \
  --control-fixture-sha256 EXACT_CONTROL_FIXTURE_SHA256 \
  --output /absolute/fresh-report/default-headers.json \
  --retain-directory /absolute/fresh-report/seven-default-sources
```

The output parent must already exist. The optional retain directory must not exist. Both must lie outside the staging, payload, imported-data and client-work roots. Omit `--retain-directory` for metadata/parser inspection only. There is no asset selector, arbitrary filename, recursive capture or network option.

The source-admitter first requires every local execution dependency to match the current committed Git bytes. Source hashes are checked again immediately before C compilation and native execution, and the compiled executable SHA is checked before and after it runs. It pins the exact control receipt, staging helper and packaged guest sources. It reuses only exact source-pinned .31 `import_identity`, native/data identity functions, `CheckedInputResolver` and `texture_inputs` through isolated read-only function/class namespaces. Original resolver and typed-error import services are explicit; guest module initialization and all `prepare`/write functions are excluded.

The cold worktree path is recomputed as `owned/client-work-<content_sha[:24]>` from the known imported-data path, verified package/cache/prerequisite archives and original identity functions. The one exact `client-work.json` must match the full content identity, key, input count/bytes and readonly contract. No glob or fallback owner is searched. The pinned read-only texture inventory supplies actual case-preserving paths while matching the seven fixed lowercase logical names. It handles the original importer directory spelling without inventing a filesystem search rule. Imported and private work-data roots, file/link targets, helper/receipt bytes and metadata are checked before and after inspection/publication. The original 173,011-leaf import proof is reused from its pinned control receipt; this adapter does not independently rehash that entire import.

The fixed allowlist remains the seven entries in `../texture-seed-eligibility-20261017/required-default-inputs.json`: white, grey, invisible, black, dummy_bump, dummy_dynamic_cubemap_face0 and buildingLightPattern. Exactly 16,514 authentic source bytes are required when actually run. The known historical whole-file hashes remain mandatory even if a decoder refuses the format.

Only after all seven source bodies pass does the C driver call the existing `coh_asset_texture` parser. It records every exact body hash and parser status. It attempts one atomic existing `coh_wr_tex_inputs_build` owner only when every protected parse succeeds; its own rejection stays explicit. The existing owner accepts only bounded legacy 2D DXT1/3/5 wrappers, safe names and no basic-key collisions. Real default codec/cubemap/TX2/mip support is still unknown. Label 1 is local inspection bookkeeping only. The temporary owner and loader are retired before the driver exits; no production owner is published.

Optional retention is independent of parser support. The only allowed raw filenames are seven fixed `.texture` names plus `manifest.json`. Each body is written exclusively, flushed, fsynced, made readonly and verified. A sanitized public-source manifest commits last within that directory; it contains fixed logical paths and source receipt hashes, with no host path, profile, account, SQL or capture data. The JSON report commits after retention and final source checks. On failure, cleanup independently attempts every owned output and the directory. It preserves the original write, flush, fsync or source refusal through close and cleanup failures. A secondary I/O failure or changed output can leave a node behind; the sanitized failure JSON exposes only fixed secondary failure codes and counts, never paths or secondary exception text. Existing outputs are refused and preserved.

Controlled qualification exercises fifteen unit methods, simultaneous write/flush and close errors, directory fsync and close errors, independent unlink failures with continued cleanup, source checks before compilation and execution, executable mutation, every one of the nine body/manifest/report write positions, source changes after manifest and report publication, escaped/writable/changed inputs, helper/receipt tampering, wrong-owner roots and output overlaps. Release, ASan and UBSan each execute supported seven-header, unsupported DX10, malformed source and supported-DDS/wrong-header-name cases, plus fixed arity/size refusal. The actual production C compilation/call bridge also executes. The public 50,644-byte gzip fixture contains only four exact original .31 Python source files, SHA256 `8a62c21674d020ad73eed9e340a740133b9eb167ee05a0a3a45c0f15ca76e172`; it contains no texture or private runtime bytes. No old qualifier is run.

The remaining namespace gap is substantive. Original `fileLoadDataDirs`, `FolderCacheNodeAdd` and `fileScanAllDataDirs` establish folder/PIGG order, timestamp-sensitive overlays, ignore prefixes, mode/quickload behavior and scan order. `texLoadHeaderProcessor` adds LWC stage-dependent skipping. `texFillInBind` keeps the first basename hash owner while still retaining other array entries. The existing header owner deliberately caps at 256 and refuses collisions, so batching it cannot establish that global table. The read-only header-index inventory and COHTHI cache preserve useful full-path/header facts but are not those basename/overlay semantics.

Original defaults must then be associated with the same live namespace owner, including invisible alpha clearing. Composite creation, the new material-trick eligibility gate, scene/locale permutations, effective Basic sampling, capabilities/TexWord and `texSetBinds` remain separate producer steps. A faithful native implementation bound to an actual immutable provider can eventually establish native ownership without deploying the original Game executable, but matching historical labels or file hashes alone does not do so. The GROUPS runtime itself starts DbServer, MapServer and native protocol capture; it has no Game CLIENT table witness.

Current provider generation, full namespace, actual default object identity, effective material, GPU/world authority and Android execution remain false. No new default or other asset is downloaded, no GEO is acquired and no raw artifact is exported by this qualification.
