# Explicit v5 CPU preparation and legacy LOD input

`coh_wr_rigid_v5_acquire` is a separate exact-version-5 CPU entry. Existing default/source v0/v8 APIs, the explicit v7 entry and SourceBody bridge retain their previous policies. This tranche adds the exact v5 policy to the private helper; it does not enable versions 2–4 or promote material, instance, source-generation, GPU or world authority.

Version 5 is not admitted merely because its model header parses. Original `geoLoadStubs` reads five size fields, then texture/model/partition blocks, a legacy LOD block, ModelHeader and variable model records. Original `readModel` uses eight 12-byte packs (no reductions or reflection pack), reads ID at offset 200 and sets CLIENT autolod distances to -1 for these versions. `allocModelList` zero-initializes omitted runtime fields. The separate `unpackLODInfo` branch interprets `ModelLODInfoOnDisk_v5` as a 148-byte row: count plus six 24-byte scalar records.

The new module validates the raw LOD span against model count and ModelHeader position, count 0–6 for every row, and finite values for all active five-float records. Negative/excess counts fail; nonfinite active values are outside this supported slice. Raw flags, inactive cells and source-permitted trailing bytes remain intact. These are input checks, not effective CLIENT LOD selection. No distances, trick flags or reduction meshes are applied.

The authentic retained body is `data/object_library/villain_lairs/tech/structure/platforms/platforms.geo`, 3,162 bytes, SHA256 `e1462116a522be747e72ddaccf353c25c17d8d510246704563affa54695ec6c5`. It has 14 original model rows and a 2,072-byte legacy LOD table. The selected captured root owner is whole-join ordinal 14026, `tek1_pltform_ramp`, original disk row 13 and observed sorted runtime row 7. Its 10 vertices/four triangles use a genuinely compressed POSITION channel (39 packed bytes, 65 delta bytes) and two exact original partitions: `tek1_main_uprwall01.tga`, then `tek1_blcny_flr_fill.tga`.
