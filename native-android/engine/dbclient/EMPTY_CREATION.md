matching empty slot. It consumes an object-lifetime attempt after admitting the
private ordinary-auth CHARACTERS context, before reading any request input.

name, and source PRIMAL_HERO1. The original server still owns validation and
allocation; printable ASCII1..63 is a native domain, not server name acceptance.

and typed existing-character handoff takes refuse before disconnect/allocation.

the original create-empty route, not an independent SQL inspection. Cancellation
cannot undo a persistent allocation or imply its request was not processed.

Pointer/alignment/known-alias retirement refusals preserve the offer and output;
an admitted policy refusal consumes and retires it. The core remains single-owner
and nonreentrant. A future opaque outer owner must guard every callback/reentry,
keep actual Auth/crypto/transport leases alive through cleanup, consume before the
bridge and poll cancellation before request and public completion. The completed
empty-list development owner remains unchanged and cannot continue into this API.
No Map socket, initialized character, save, READY, character/full-update ACK,
current generation, gameplay/world publication or actor authority is supplied.

The focused new harness uses only public session methods and actual original

project allocation balance, and socket descriptor balance. System/zlib/process
RSS and a global owner budget are not admitted. No actual Auth/DH/encrypted DB,
DbServer, MapServer, registry, SQL or original server allocation runs.

canonical fresh context (zero lifetime choices implies zero selection count).
