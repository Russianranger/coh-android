owned-file diagnostic sink. No original/protected source tree is edited. No
server build, Wine/Windows run, workflow dispatch or new capture is performed.

unchanged. Compile/runtime qualification of a staged original Win32 server is a
future coordinator decision.

## Export overlay and exact hook

stage.py verifies LF-normalized pins of original costume_data.c, svr_init.c and
initCommon.c. Given independently prepared generation/inventory/profile/run
metadata, it writes a FRESH external OVERLAY ONLY. It never builds or executes.
It refuses changed source, unknown metadata keys, zero/invalid IDs, invalid
32-bit generation, preexisting output and output inside the source tree.

The only source changes in that overlay are:

- Append pure serializer and sink includes to Common/gameData/costume_data.c
  under SERVER&&!TEST_CLIENT, where initialized ordinary/extra/palette globals
  and original public getters are accessible.
- Declare and call coh_source_costume_snapshot_startup in MapServer/src/svr/
  svr_init.c immediately AFTER original loadCostumes(), before
  loadPowerCustomizations(). Original initCommon.c loads body parts via
  bpReadBodyPartFiles; serializer still refuses zero/invalid count if the target
  startup sequence did not initialize them. No earlier builder is skipped.

The helper walks EVERY original index0..stashGetMaxSize-1 with original
stashFindKeyByIndex/stashIntFindKeyByIndex, preserving holes/deleted slots,
present empty strings, palette keys, full max_size and valid counts. It reads
GetBodyPartCount/getBodyTypeCount directly. It refuses string>259, unknown
capacity/counts, invalid palette zero, size/count mutation between the boundary
reads, output>4MiB, body parts outside1..29 or body types!=9. The source tables
and keys must remain FROZEN throughout export; endpoint count checks cannot
detect same-count concurrent content mutation. The exact startup hook is an
original initialization boundary, and any future runner must prove callbacks or
reloads are quiescent. No hashing, reinsertion, sorting or asset interpretation
is performed by the helper. Pure-helper input IDs, scratch buffer and written
pointer are caller-owned/disjoint immutable metadata; only this private sink
invokes it in a staged server. Scratch may change on refusal; written commits
only on full syntax success.

If COH_NATIVE_COSTUME_OUTPUT is unset, the diagnostic hook does nothing. If set,
path must be bounded absolute (Windows drive-rooted, no '..'). Sink allocates
ONE4MiB scratch buffer, serializes fully, then creates an EXCLUSIVE new file,
never overwrites an existing file. Short write/close failure attempts removal of its owned
partial file. If removal itself fails, return3 and an explicit CLEANUP_FAILED
marker report the retained owned path; no successful cleanup is claimed. The
future capture driver must preserve that evidence and finish owned cleanup.
Crash/power-loss cleanup is external; a file alone is insufficient
evidence. A completion marker appears only after complete write and close.
Output hash, compiled binary/source pin, actual loaded bins/parser/cache choices,
process/run/profile, generation and cleanup must be recorded by the coordinator
and bound independently before native import. No truth-valued capture/actor
certificate is written into the serialized body. The sink's metadata IDs are
build inputs, not self-authenticating claims about actual runtime files.

## CLIENT-specific and remaining input differences

SERVER/TEST_CLIENT loadCostumes uses shared costume.bin, supergroupColors.bin
and tailorcost.bin with source preprocess and fillExtraData callbacks. Full
server startup selection/normalization/fallback must be observed. Pure CLIENT
adds supergroupEmblems.bin, costumeVerifyTextures and editnpc alternate path
selection/reload callbacks; the same shared function has CLIENT-only tagged
part/UI processing and SERVER-only reward-hook calls. This exporter captures
only ordinary/extra/palette tables used by the admitted wire grammar, not
reward/tagged/GeoData/UI state, texture validation, bodypart geometry/rig maps,
power customization dictionary, account entitlements or any asset resources.
A native Android client can use the captured server dictionary directly only
under its admitted generation, without pretending those CLIENT-only systems
have been replicated or qualified.

## Qualification boundary

Host tests execute UNCHANGED original source stash getters, width/log2i,
body-type table/count and palette function on SYNTHETIC stash layout/content.
The new serializer output is then consumed by the frozen native importer,
including holes/deleted slots/present-empty palette keys, all short capacities,
late count mismatch, invalid source slots/counts, owned sink/no-overwrite and
bad paths. Body-part count is a declared synthetic fixture shell. Actual
original stash hashing/insertion/resize, Parse6 reader/builder, whole source
server, 32-bit ABI/Win32 sink and real cached bins are NOT executed here.
ASan address/UBSan cover compiled host new code and extracted source helpers;
LeakSanitizer is unavailable in this container. OpenSSL external implementation
sanitizer/stack closure is false. No authentic dictionary export, source/runtime
capture acceptance, actor/ACK authority, Android build or physical test follows
from these host tests.
