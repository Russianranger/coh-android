# Disabled original BodyPart MapServer target qualification

`body_witness_target.py` composes the existing disabled witness onto the
separately staged, exact original `map_startup_certified_animation` source.
It reconstructs that inherited receipt with the existing source preparation
implementation and verifies every inherited source/overlay identity. The
original BodyPart and parser must still be byte-identical before instrumentation.
Existing startup progress hooks are retained; removing precisely the new
witness prototype/call reconstructs the original inherited startup bytes.
Build/profile/run labels remain explicitly unauthenticated labels. No generation
input, database connection, runtime launcher, deployment or dictionary admission
is provided.

The new narrowly triggered `native-body-runtime-target.yml` workflow acquires
the same exact published startup inputs, prepares only an external disposable
source tree, compiles `MapServer` with the existing VS2026 Win32/OptDebug preset,
and records the actual PE32/i386 executable. CMake/MSBuild use two workers;
MSVC's original `/MP` is bounded to `/MP1` through its final `_CL_` option.
Compilers, generators and their mandatory build-time checks can run. The
MapServer executable never runs. Accepted server binaries and working databases
are not accessed or modified.

The recorder verifies exact original startup files again, actual generated
compiler-information files, selected compiler executable hashes, generated
MapServer project and SDK version, populated CPM source-cache bytes, and the
actual generated target's evaluated SDK/MSVC include and Win32 library bytes.
Detailed manifests and compiler logs belong to the CI artifact. Each manifest
has at most 20,000 entries and 768 MiB named input bytes; individual files are
limited to 32 MiB and streamed one at a time where copying is needed. This is
build-input accounting, not total compiler RSS or Android RAM. The inherited
producer remains at 65,860 host-x64 static bytes, zero new heap allocations,
65,536 payload bytes and a 4 KiB observer stack reservation. No runtime-process
reservation is inferred from these observer-owned amounts.

Preflight/composition controls run with:

```sh
python native-android/engine/costume-export/test_body_witness_target.py
```

The existing producer's release/ASan/UBSan qualification remains independently
reproducible with `check_body_witness.py`. New Python preflight code has no
sanitizer claim. Full target compilation and its actual compiler/SDK dependency
receipt remain pending until the hosted Windows job genuinely succeeds.

Even a successful target compile observes no loaded rows and admits no source
runtime generation. The next runtime prerequisites are an isolated disposable
runtime/database, independently established executable/source/profile/run and
coherent selected Map/session/load-generation ownership, and the exact selected
cache/shared-segment identity. No current MapServer catalog, default count,
immutable dictionary generation, complete initial transaction, actor, READY,
RECEIVED_CHARACTER or application ACK follows from staging or compilation.

## Bounded cycle result and recovery

The original MapServer target compiled in both hosted attempts: runs
39363378870 and 39365299854. Complete target qualification was refused.
The first attempt could not locate MSBuild from an absent CMake cache field;
the second correctly bound the selected VS instance but refused the combined

retained, so the actual differing operand/UCRT selection is unknown. The
project declares Windows SDK 10.0.26100.0; that declaration cannot replace
an effective SDK/UCRT input observation. No third full build is part of this
cycle.

Run this only in a compatible Windows environment. It evaluates the retained
