# Authentic disposable server evidence contract

A full-server interoperability receipt must identify the test mode explicitly.
The source-function oracle receipt in this directory cannot be substituted for
any item below. Do not disable checksum/version policy to manufacture success.

| Required identity | Capture without secrets |
|---|---|
| Client | Native source commit, exact executable/APK SHA256, ABI, crypto provider receipt |
| Server | Exact source revision/overlays, Auth/DB/Map binary SHA256, existing artifact/run receipts and checked dependency versions |
| Configuration | Hashes and reviewed nonsecret effective protocol version, encryption policy, checksum/native-client policy and auth mode |
| Disposable ownership | Explicit local test namespace, isolated database/SQL schema, loopback-only listener inventory, fresh account/character identifiers represented by test labels |
| Startup | Real processes, readiness evidence, matching data/template/bin hashes, selected character's actual saved map |
| Traffic | Monotonic relative times, direction, endpoint role, datagram sizes, packet/control/command IDs where safely available, ACK/reliable/ordered/compression transitions |
| Login | AuthServer hello, encrypted credential request without its body, accepted AuthServer response, shard/play response, DB session acceptance |
| Character | Actual DB list/selection result, independently checked chosen identity, actual MapServer handoff/cookie transition without cookie values |
| World | Authenticated MapServer acceptance, server-authoritative initial character identity/pose, required scene/entity parse and render handoff, explicit unsupported tails |
| Failure recovery | Malformed/unsupported cases, controlled loss/reorder, retry limit, disconnect, foreground/new-session recovery, clean ownership teardown |

Never include passwords, credential derivations, private/public DH buffers,
shared secrets, key schedules, RSA plaintext/ciphertext, auth cookies, session
keys, raw config files, raw credential packets, or unredacted packet captures.
Use redacted structured protocol observations at owned process boundaries.
A full raw capture requires a separate private handling process and must not be
committed as public qualification evidence.

Keep independent booleans for `source_function_oracle`, `full_server_netlink`,
`real_authserver_login`, `development_fake_auth`, `db_character_selection`,
`mapserver_acceptance`, `authoritative_spawn`, `android_execution` and
`physical_thor_accepted`. A successful NetLink connection must not set any
Auth/character/world flag. `development_fake_auth=true` requires
`real_authserver_login=false` unless a separate authentic login is independently
recorded. A prefix parser must not emit a live-world acceptance witness.

Use one consolidated native APK only after that integrated application path is
meaningfully testable. Keep the physically accepted Session Client 0.3.0 and the
conventional client available throughout.
