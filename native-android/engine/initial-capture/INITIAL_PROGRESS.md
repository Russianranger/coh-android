# Separate post-queue receiver observation

Actual scene39152328226 accepts the complete original catalog/runtime/resources/
bounds/GROUPS associations through the changed streaming verifier. The frozen
native receiver still observes one queued REQALLENTS and no initial packet.
The existing complete original source review establishes that first ALLENTS
precedes READY, received-character and full-update ACK. Those inputs stay refused.
Queue admission alone does not establish socket emission or server receipt.

The NEW receiver-main role adds a112-byte fixed scalar witness. Successful
original begin binds its one actual opaque owner. A returned original service
that reports the complete one-shot GROUPS/request state records queue observation.
Subsequent calls with the same owner and generation fields, WAIT_ALLENTS and an
already closed DB are counted. The existing sendto call is link-wrapped: it is
called exactly once with unchanged arguments and its result/errno are returned
unchanged. A full successful result during that post-queue owner service counts
an emitted datagram. Would-block, interrupted, partial and other errors have
separate counts. No frame, endpoint, FD, credential, character record or packet
identifier is copied into the witness. The opaque owner key is cleared before
its original destroy call. A replaced key, state/generation mismatch, reversed
clock, reentry, malformed callback result or million-event ceiling refuses only
the observation; it does not suppress or change the original protocol call.

These are **command-unattributed post-queue datagrams**. They may include ACKs or
other pending transport traffic. They do not identify the request's Tx packet,
prove a particular command was sent, or prove original server receipt/parse.
The service count means calls entered on the original owner API, not a separate
UDP-pump counter. Offsets use the unchanged monotonic time argument of those
service calls relative to successful begin. The queue offset identifies the
service containing the observed queue event, not an independent wall-clock
measurement inside serialization. No deadline, pump or retry is added.

The legacy main body is mechanically preserved with five reversible call/name
edits: rename main, wrap begin/service/destroy, and write the optional new fixed
receipt before the actual owned output-directory FD closes after GROUPS capture
success. Existing stdout and private capture/initial receipts remain exact.
`request-progress.json` has its own v1 schema, at most1024 bytes, mode0600 and
exclusive no-follow creation through that owned FD. A failed write is removed;
no extra file is written for a failed GROUPS capture. Report failure never
changes legacy success, failure or return codes. It is not accepted by an old
public status/schema reader implicitly: future source-admitted orchestration
must explicitly validate/project this separate role and receipt.

Focused new controls use explicit begin/service/diagnostic doubles plus actual
link-wrapped POSIX loopback sends and an actual EBADF error. They cover queue
with no later service, later service without emission, actual pre-queue send
exclusion, actual post-queue full send, errno/return preservation, synthetic
would-block/interrupted/partial classifications, generation/phase/DB/owner/clock/
reentry/counter/retirement guards and bounded fixed JSON. Release/ASAN/UBSAN run
only this new unit. The full production role is freshly linked in all modes
using the accepted per-source O0 policy for unchanged protocol and Blowfish,
then only its unchanged no-argument refusal executes. No earlier fixture or
qualifier entrypoint, original server or actual DB/Map session is run. The new
release ELF is retained for exact future admission; other temporary binaries
are hashed. Sanitizer leak detection remains disabled.112 bytes and bounded
stack/receipt storage are additional named diagnostic storage, not whole-process
or96MiB aggregate/RSS/GPU fit. No actor, ACK, source token or world authority.
