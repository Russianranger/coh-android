# Original Map initial-response observer (new diagnostic role)

This role observes the one original Map owner whose successful, fully committed
GROUPS boundary is captured by the accepted fresh callback observer. It changes
no original command, packet bit, queue, state, callback, timer, condition or
return. It does not publish an actor, permit an application ACK, admit a source
generation or grant world authority.

`sourcehooks.py` accepts five entire LF-normalized, hash-pinned baseline files:
the accepted fresh group TU and its profile, the inherited prepared
`svr_tick.c`, and original `entsend.c` and `entserver.c`. The tick input includes
the accepted progress, character-event and monorail patches from the complete
startup source preparation chain; it is not raw upstream. Four new overlays live in the group directory;
the adapter includes the portable implementation exactly once. Both LF and
uniform CRLF reverse byte-exactly. Every baseline mutation is refused. No
upstream file is changed by the supplier.

The successful original GROUPS `finish` result is observed once. Its link is
saved before the original boundary clears it, and only success binds this ledger.
Afterward the adapter uses fresh registered membership, link/client/entity and
character backlinks, entity table/state, and immutable identity values on each
owner event. It accepts the real sleeping/active entity and REQALLENTS ready-state
transition; it does not reuse the earlier NOT_READY prerequisite. Foreign links
and entities do not advance the ledger. The accepted GROUPS installation thread
is immutable before these hooks become reachable; every hook checks that owner
thread before reading mutable ledger/key state. Other threads are ignored, not
allowed to write a racing refusal. Portable core calls require serialized ownership.

The sequence records normalized CLIENT_REQALLENTS dispatch, original state
writes, tick entry/backpressure/transfer checkpoints, selected full-update
arguments and viewed-entity equality, SERVER_ALLENTS header, whole character
entry, `character_Send` entry/return, whole sender return, packet attachment,
active-entity finishing, and the final same-packet `pktSend` invocation/return.
Character hooks introduce no nullable client dereference. The packet address is
converted to a private integer before the call, never dereferenced afterward.
Post-call results require this exact pending token. `entFreeDbg` retires matching
private keys before original unlink/free; a changed registered owner refuses and
retires before reuse. First refusal and first terminal outcome remain fixed.

`pktSendDbg` may fragment and return zero after children were enqueued. Thus raw
zero is a valid observed return, never a queue-failure claim. This role does not
observe fragment children, accepted whole queue, packet callbacks or sockets;
`packet_queue_acceptance_established` and `socket_send_established` are always
false. Its final pre-call bits/compress/order/reliable fields describe the
original uncompressed constructed packet, not compressed wire size or fragment
count. `FINAL_RETURN` means only this synchronous milestone was reached.

The caller precreates an empty private single-link regular file under its owned
parent and exports `COH_NATIVE_INITIAL_SEND_LEDGER_OUTPUT`. The adapter opens only
that existing path, denies sharing/reparse points, retains one handle and its
file identity, and emits at most 4096 bytes using the exact 46-key
`coh-server-initial-ledger-v1` schema. All identity keys remain private. Public
projection uses `schema.parse`, which rejects extra/duplicate fields, bad types,
unknown states, invalid domains and all authority claims. `fixtures.py` supplies
only synthetic control snapshots.

Writes occur at first milestones/state observations and power-of-two owner ticks,
with a hard 128 ordinary-write limit. Diagnostic limits only retire this observer.
Error codes (`GetLastError` and `errno`) are preserved across every exported hook.
On I/O failure the same owned file is best-effort truncated, never reopened or
replaced. An ACTIVE receipt is **only the last successfully persisted checkpoint**;
it cannot establish absence of later events, final counters, complete process
lifecycle, or continued sink health. A failed invalidation can leave that earlier
checkpoint. Even FINAL_RETURN is diagnostic evidence, not queue/socket or client
acceptance. Runtime collection separately owns child/file identity, cleanup,
GROUPS byte pairing and transaction admission.

`check_observer.py` executes the portable core and this production adapter with
explicit synthetic Map/Win32 providers in release, ASan, and UBSan modes. It tests
strict parsing, owner/key mutation, sleeping ready1 binding, unrelated/foreign
calls, thread exclusion, packet association, pre-free retirement, raw return0/1,
write throttling/limit, I/O refusal/invalidation and error preservation. Six exact
executed host ELFs and raw outputs are retained. Original Map, its serializers,
Windows kernel behavior, and any actual session are outside that host proof;
the distinct original Windows build and actual transaction must qualify them.
