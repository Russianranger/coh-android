# Conditional source-default admission (nonshipping)

The physical Combined 0.1.11 result remains the unchanged stage41 refusal. A
flag0 has no encoded count: original `costume_receive` obtains
`GetBodyPartCount()`, whose unchanged source returns
`eaSize(&bodyPartList.bodyParts)`. A retained CLIENT cache row count, native
capacity30, a source hash or a caller default does not supply that runtime value.
Flag1 retains its independent Pack4 framing and still needs the same catalog
checks. Existing `coh_initial_partcount_probe`, numeric stage41/43 projections,
JNI, report ceiling, parser policies and accepted APK are unchanged.

`coh_initial_partcount_admission` is an additive nonshipping consumer. It starts
at the exact previously established appearance/bodytype cursor in one immutable
ALLENTS loan. It replays existing appearance/SG/scales/count observers and reads
the original bodytype again from that prefix. It checks exact packet-span,
logical-bit-length and compressed-profile equality to C's binding descriptor,
then queries the opaque costume owner. Original bodytype `< getBodyTypeCount()`
and part count `<= GetBodyPartCount()` checks occur before every part/cache/index
bit. No raw bodytype is retained. Native part capacity30 and dictionary type
capacity64 remain narrower safety limits; neither is a source runtime count.
Explicit0 also requires an admitted owner and stops before costume completion.

A passing conditional source/owner gate (only a test double supplies a successful
query in this qualification) returns UNSUPPORTED/PART_BODY, with the count cursor
unchanged and no part read. Missing, stale, mismatched, retired, coherent but
unadmitted or oversized owners cannot supply a default. C's validation-only
output-disjoint API runs before replay/publication to reject output aliases into
its owner, witness, dictionary or static source-definition storage. The input
reader and packet remain unchanged. There are no persistent owner allocations,
new reservation tickets or borrowed pointers retained by A. The actual parent
must keep packet and provider leases alive and account for their complete
source/dictionary/dependency allocations, old/candidate owners, allocator slack
and the unchanged16KiB native call reserve. This does not install a generic
working-set ledger adapter or measure Android RSS/PSS.

Production `coh_costume_owner_query` deliberately has **no COH_OK path** until an
independently authenticated runtime producer lease exists. Candidate content
integrity and source/build/profile/run labels do not prove a loaded generation.
The positive gate branch is qualified only by an explicit linker-substituted
synthetic query in the standalone test. That substitute is never a production
owner constructor and is never linked into Android. Current-server BodyPart
rows, loaded dictionary association, source/run/session/generation/loan leases
and immutable lifetime through this ALLENTS transaction remain unresolved.

The checker pins the original files against the accepted source manifest,
extracts whole unchanged `costume_receive`, `GetBodyPartCount` and
`getBodyTypeCount`, and retains the exact source bodytype enum/table. It executes
720 source boundary cases using an independently implemented bounded fixture
packet reader and synthetic earray count. This is an original consumer grammar
qualification, not MapServer execution or a real runtime catalog observation.
The oracle is compiled unsanitized; the new native consumer runs release,
ASan and UBSan separately. Tests cover missing/stale/mismatched owner refusal,
flag0 counts1..30, explicit0/count/cap boundaries, bodytype-before-part ordering,
all packed starts, both profiles, every prefix truncation, malformed binding,
API/packet/opaque-owner aliases, endpoint overflow and direct allocation-call
interception. LeakSanitizer is explicitly disabled under host restrictions;
there is no process-wide allocation or leak-proof claim. Compiler frame evidence
is separate from source payload accounting and device RSS/PSS.

No live stage41 progression, complete costume/character/ALLENTS acceptance,
selected-character ownership, actor/world publication, READY,
