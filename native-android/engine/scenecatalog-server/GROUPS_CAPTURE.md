# Actual original GROUPS capture role

`stage_groups_capture.py` closes the previously missing private hook/sink
installation. It reuses the exact source-pinned `source_groups_boundary.inc`
producer: actual registered NetLink/client/entity ownership, complete saved
catalog, root/future snapshot, model/resource observations, raw public-bounds
decision ledger, PRE-producer saved/force/timestamp eligibility, and the exact
original logical GROUPS packet from the same `worldSendUpdate` call.

The new sink accepts no credential, selected DBID, caller generation, detached
source data, or claimed source/run digest. The original owner preparation derives
the actual source character/link. Installation records the actual normal-map
startup thread after `groupLoadMap` and `dbSetupMap`; observation refuses another
thread. The real existing model/LOD guard checks initialized original loader
state and empty queues, holds both original try-locks through the entire source
transaction, and verifies folder callbacks are disabled/manual. No hook invokes
the engine, performs a lazy load, or changes source/server protocol state.

This is a **nonshipping private diagnostic build**. No accepted APK, source
MapServer, profile, character, persistence, ordinary service policy or application
ACK behavior is changed. Original `pktSend` still executes normally if capture
refuses. A source packet capture is explicitly **pre-pktSend** evidence; only
correlation with an actual owned native receive can establish delivery.

## Build and run interface

Apply to a fresh private `prepare_map_startup_source` tree, before configuring and
building its existing Win32 MapServer target:

```sh
python native-android/engine/scenecatalog-server/stage_groups_capture.py \
  --source-root "$ROOT" --already-staged "$PRIVATE_STARTUP_TREE"
python native-android/engine/scenecatalog-server/stage_groups_capture.py \
  --source-root "$ROOT" --already-staged "$PRIVATE_STARTUP_TREE" --verify
```

After the existing Visual Studio Win32 OptDebug MapServer build, record the exact
PE, original build-input identity, inherited private source, inline suppliers,
new source transformation, anim.c quiet guard and source sink:

```sh
python native-android/engine/scenecatalog-server/record_groups_compile.py \
  --source-root "$ROOT" --staged-source "$PRIVATE_STARTUP_TREE" \
  --inputs-receipt "$INPUTS/map-startup-inputs.json" \
  --output "$COMPILE_OUTPUT" --require-clean
```

Only the explicit private run receives:

```text
COH_NATIVE_GROUPS_TRANSACTION_OUTPUT=C:\private\live.cohgtx
```

The parent must already be privately/exclusively owned and stable. The existing
Win32 path checks reject reparse parents, device paths, ADS, dot aliases, DOS
devices and unexpected lookup errors. The sink never creates a directory or
replaces a destination. It opens `.partial` with `CREATE_NEW`; all callback bytes
are synchronously streamed, no capture body is retained on the source heap.
After packet/owner checks and successful actual quiet release, it appends a
commit footer, flushes, closes and renames without `REPLACE_EXISTING`. Each
process permits one actual open attempt. Cleanup preserves/report remaining
partial output when the OS refuses close/delete. A failed or incomplete output
cannot appear as a successful committed envelope.

The original named source output cap remains128 MiB. The streamed envelope adds
bounded per-chunk framing under a160 MiB total cap; original Packet allocator
growth and whole-process RSS are **not** bounded by that number. The existing
128 KiB boundary record scratch is reused. There is no eager packet/catalog
copy in the new sink.

## Envelope and extraction

The64-byte `COHGTX01` header records version, observation ID and original owner
thread ID. Every subsequent chunk has four little-endian u32 values: kind,
observation ID, body bytes, zero-based sequence. Contiguous kind blocks occur in
this exact order:

| Kind | Actual observed data |
|---|---|
|1|192-byte original owned-client/entity record|
|2|Complete source COHCAT stream|
|3|Complete original root/future COHRTS stream|
|4|Complete original model/resource COHRES stream|
|6|Complete raw public-bounds decision ledger|
|5|Original PRE-producer eligibility records|
|7|192-byte packet flags and exact supplier counts/CRCs|
|8|Exact original packet allocation prefix through logical bit extent|
|9|128-byte commit footer with exact total/chunk/per-kind counts|

`inspect_groups_capture.py` validates framing, monotonic sequence, all required
blocks, caps, source header associations, counts, exact end, packet flags and
commit footer. It hashes and optionally extracts using64 KiB reads:

```sh
python native-android/engine/scenecatalog-server/inspect_groups_capture.py \
  live.cohgtx --extract /fresh/private/extracted
```

Source symlinks/hardlinks, truncated/contradictory output and existing extraction
destinations refuse. Failed extraction removes only its new outputs. The result
reports source owner DBID/entity/map observations and exact individual SHA256s.
It deliberately leaves provenance, run identity, actual native receive, raw
cache-computation equivalence, source-generation admission and world authority
false. A syntactically valid, self-described altered positive DBID cannot grant
authority; the independent actual ownership/provenance chain must reject it.

## Qualification and remaining live inputs

`check_groups_capture.py` executes the actual new sink, original catalog/runtime/
raw-bounds/world producers, boundary, eligibility and transaction hooks together.
Release/ASan/UBSan each pass12,340 checks, including142 create/write/short-write/
flush/close/rename refusals. Tests cover final/partial collisions, unexpected
lookup errors, path reparse/dot refusal, thread mismatch, callback mode, one-shot
observation, aggregate refusal, exact original packet bytes and commit counts.
Quiet/entity/resource providers and WinAPI are explicitly substituted; actual
source owner and quiet functions retain their independent existing source tests.

`test_groups_capture_inspect.py` qualifies the emitted synthetic fixture with
every-byte truncation, framing/header/count corruption, extraction rollback,
symlink/hardlink refusal and descriptor cleanup. This is parsing qualification,
not authentic server capture or generation acceptance.

Remaining required execution inputs are the actual qualified Win32 build/layout,
fresh private source/runtime asset inventory and run receipt, controlled original
DbServer/MapServer deployment, real account-owned native local DB-to-Map handoff,
actual source packet plus native opaque-owner receive records, and exact
transport-command normalization/comparison. No previously retained startup
catalog/resource capture is relabeled as this witness. Only a specifically new
same-boundary capture may close it. Original CLIENT imported-cache/material/LOD
semantics and complete authoritative player publication remain separate gates.

The restore supervisor admits two fixed native build roles. The existing
`coh-local-scene-capture-build-v1` driver and return shape are unchanged. The
new `coh-local-initial-capture-build-v1` role selects only
`check_local_initial_capture.py`, `capture_local_initial.c`, and the executable
basename `coh-capture-local-initial`. Its receipt must declare the seven strict
Boolean flags for a nonshipping initial observation, GROUPS scope and one
REQALLENTS send, with application character acceptance, READY, received-character
and full-update ACK sends all false. Both roles require authoritative build
hashes, the selected fixed driver's literal `RELATIVE` list, the C tool source,
all compiler-derived project headers, and the exact ELF bytes. Receipt-supplied
driver selectors have no effect. The eight `test_initial_native_input.py`
controls use synthetic source/ELF shapes and real compiler dependency scans;
they execute no native capture, PG, Wine or server and grant no authority.

Only the new role records an optional `initial_observation` in the private run
receipt. After the ordinary GROUPS pair and complete owned cleanup both pass,
the supervisor checks the fixed `coh-private-initial-observation-v1` receipt
against the unchanged GROUPS receipt, packet SHA, selected owner, connection,
DB/Map generations and closed socket counts. A successful raw ALLENTS loan must
follow that GROUPS message generation, report one REQALLENTS, and retain at most
4 MiB with exact packet SHA, bit/cursor/profile, bounded shortcut and update
prefix metadata. This binds the native tool's observation; Python does not
interpret the entity or character tails.

The two optional files remain under the private `native` output. An absent or
malformed observation yields a fixed private status. A well-formed diagnostic
refusal may retain only its zero-payload receipt. None of these outcomes changes
a valid GROUPS result or the immutable source-snapshot token's scope. Exclusive
copies recheck exact bytes before/after flush, fsync and close; any refusal rolls
back only the newly owned optional files and records whether rollback completed.
Thirteen `test_initial_observation_binding.py` methods cover strict receipt/owner
binding, private real-file policy, failure shapes, cleanup ordering and late I/O
rollback with synthetic packets. No initial character, actor publication,
READY, received-character, full-update ACK or world authority is admitted.
