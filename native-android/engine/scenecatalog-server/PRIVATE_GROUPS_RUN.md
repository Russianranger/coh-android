# Private existing-character source/native transaction supervisor

`capture_groups_transaction.py` adds the missing runtime extension to the
qualified owned PG/Wine supervisor. It consumes an independently pinned original
observer compile artifact, the exact native local capture build and an authorized
existing PostgreSQL custom-format backup/account/wire slot. It never inserts an
account, substitutes a DBID, seeds a minimal character row or creates a character.
Missing/private-invalid dump or account inputs refuse before compiler or runtime
process creation.

The source MapServer artifact is checked by `admit_groups_capture.py` against an
independently supplied compile-receipt SHA256, all emitted artifacts, the exact
private-stage transformation/inline suppliers, inherited startup receipt, actual
new sink and anim.c quiet guard. The native executable is checked against its
independently supplied build-receipt SHA256, ELF x86_64 identity, binary SHA256
and actual compiler-discovered project C/header dependency bytes. This permits
qualified reuse across unrelated source commits without pretending that matching
commit labels alone establishes binary equality.

The runtime requires the existing exact published control fixture and .34 donor,
Wine with the existing Windows ODBC support floor, PostgreSQL tools, a nonroot
GitHub-hosted Linux x86_64 runner, a current matching `GITHUB_SHA`, fresh disjoint
private work/output directories and unused loopback ports. It creates a fresh
Wine prefix and PG cluster, restores the supplied dump into a **new** database,
checks actual existing account membership with a bounded read-only query, then
starts the retained loopback manual DbServer and private original Atlas observer.
Only after its actual listener proof does it invoke the existing native tool on
the requested wire slot. That tool derives the selected DBID through the opaque
DB-to-Map owner; no DBID/cookie/ticket is supplied by this supervisor.

Every pinned helper is additionally byte-compared to `git show <GITHUB_SHA>:path`;
an untracked or altered helper cannot claim that commit's provenance merely
because `git diff` ignores an untracked path. Development working trees may run
the pure helper tests; they cannot run the private server orchestration until
the implementation is committed into the exact runner checkout.

The new source envelope and native-owned receive must match in exact whole
logical packet SHA256/bytes/bit extent, actual selected DBID, Atlas map identity,
source/native transport profile, complete source footer counts/CRCs and exact
packet consumption. Protocol4/5 is the currently admitted comparison scope; this
supervisor rejects other profiles instead of guessing normalization. The optional
encrypted transport is configured through the existing real session provider;
the session remains explicitly **local development authentication**, not a
qualified AuthServer→DB→Map chain.

The backup is first streamed to a verified0600 file in this invocation's private
work directory. Restore reads only that copy; exact hashes are checked immediately
before and after restore and again during final cleanup. The accepted original
backup/account remain unchanged. Native receipt schema and every consumed numeric
field are checked strictly; Boolean values cannot substitute for integer IDs,
slots, map values, packet extents or cleanup counters.

Every child starts in an owned process group. Cleanup stops only those groups,
the invocation's private Wine prefix and fresh PG cluster. Both actual native
socket closures, absent process groups, input dump/account bytes, original
runtime inventory, producer binaries/receipts and native source dependencies are
verified again. A matching observation is never accepted after cleanup refusal.
No native READY/RECEIVED_CHARACTER/full-update ACK or actor is produced.

`--timeout-seconds` is a deadline for the explicitly supervised child stages,
checked between reused PG helper operations. It is **not** a strict whole-run
deadline: the unchanged PG helper uses180-second subprocess limits, or900 seconds
for dump/restore, during which health/log polling pauses. Logs are polled rather
than kernel capped, and no process RSS/heap cap is established. These limitations
are recorded numerically in the result; this extension does not alter the
qualified persistence helper to claim stronger timeout or memory behavior.

All output is private and includes `public_upload_permitted:false`. The original
dump/account are never copied into the result; raw DbServer/MapServer/PG logs
remain in the private work directory. The result's source envelope and native
packet contain source/character observations, and this workflow does not publish
them. Aggregate helper tests are separate shareable qualification evidence.

Example operator interface, with exact independently verified pins:

```sh
python native-android/engine/scenecatalog-server/capture_groups_transaction.py \
  --runtime "$CONTROL_RUNTIME" --control-fixture "$CONTROL_FIXTURE" \
  --db-donor-apk "$EXACT_034_DONOR" --compile-directory "$OBSERVER_COMPILE" \
  --compile-receipt-sha256 "$OBSERVER_RECEIPT_SHA256" \
  --database-dump "$PRIVATE_EXISTING_DUMP" --database-dump-sha256 "$DUMP_SHA256" \
  --account-file "$PRIVATE_ACCOUNT_FILE" --wire-slot "$ACTUAL_WIRE_SLOT" \
  --native-capture "$NATIVE_TOOL" --native-build-receipt "$NATIVE_BUILD_RECEIPT" \
  --native-build-receipt-sha256 "$NATIVE_RECEIPT_SHA256" \
  --pg-bin "$PG_BIN" --work "$NEW_PRIVATE_WORK" --output "$NEW_PRIVATE_RESULT"
```

The supervisor can establish an exact paired observation only after actual
runtime execution. Its parser/kernel tests do not qualify source generation,
CLIENT cache equivalence, actor state, renderer publication or world authority;
those fields remain false. The original/runtime asset and source-producer
provenance is retained for independent admission after the run.

## Existing-character input audit

All eleven retained `docs/postgresql-evidence/character-{persistence,session,
transfer}-*.zip` archives contain only report JSON and selected diagnostics.
Their four-table snapshots deliberately omit position, health, timers and other
character state (`database/postgresql/tests/character_snapshot.py`). The accepted
Thor receipt identifies the same selected saved-character projection, not a full
database backup.

The original hosted character artifact11164315967 was independently recovered by
the coordinator and verified at72,279,263 bytes, SHA256
`b360972ceec148399c1eb0758ae2b3486b4d696f3bff8964fe54850c61c82d2f`.
Its179 outer members and12 nested report members contain screenshots, console/
server evidence and the8,682-byte selected snapshot; no database/dump/backup is
present. These artifacts cannot be silently reconstructed as complete existing
character rows.

A source-produced creation route exists in the accepted standard graphical
`tools/android/interactive/character_host_smoke.py` flow, with real original Game
creator input and ordinary committed logout; `character_reopen_host_smoke.py`
checks identity continuity. Running it to produce a fresh complete private backup
is a substantial separate prerequisite. No native character-creation serializer
exists in the current native DB client. No such graphical run or PG/Wine capture
was executed in this host qualification.
