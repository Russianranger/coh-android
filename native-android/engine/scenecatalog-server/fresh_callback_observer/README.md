This is a separate nonshipping callback-sealed observer profile for a fresh
disposable source-created fixture. It addresses the source-proven guard
incompatibility retained with run39081284657. Its host qualification does not
compile a Windows PE or execute original FolderCache/server/PG/Wine code.
A new Map-only compile and independently admitted source/PE/profile identity
remain required before another live transaction. The accepted83 observer,
shipping profile, old boundary predicate, exporter bodies and original loader
guard are unchanged. Cache/watch-policy equivalence is explicitly false.

Normal Map startup enables FolderCache updates after installing the old sink;
its live boundary requires updates disabled. This role preserves that exact
normal enable call, then seals through the original disable API only when the
old sink is actually configured on the same installation thread. No existing
CLI option establishes this condition. It is an explicit source/profile change,
opted into only through this separate build role and the existing private sink
output environment. It does not change accepted profile or cache policy.

The deterministic stager instruments the actual queue reservation before
listAddNewMember, completion after original node initialization, and removal
after original listFreeMember. No queue node/list is observed. A recursive
Win32 critical section protects count/depth/epoch state, complete public poll
reservations, original plain setter assignments and all profile/view calls.
Update/callback/allocator bodies and real model-loader locks remain outside
this new lock. Seal/check/restore reject active depths before reading plain
original mode flags. Any failed count/depth/epoch increment or decrement sets an independent sticky
accounting-invalid latch. It blocks idle/plain-mode reads and restoration even
if an earlier first failure masks COUNTER_LIMIT or recorded depths later drain.
Counter overflow and later sealed setter/queue/activity changes permanently
refuse the observation. Public polling while sealed before
the observation with an empty queue is deferred; polling during the observation
invalidates it. This scheduling change is confined to the new diagnostic role.

End validates and restores/unseals under that same reservation lock. Its unlock
is the point-snapshot close; reservations admitted later are outside the
observation interval. There is no current-after-release guarantee. Restoration
refuses while actual original mutation bodies/queue construction remain active,
keeping dispatch sealed. An explicit owner abort may retry only the folder
restoration once idle; otherwise the fresh owned process cleanup ends it.
A rejected pre-mode-read seal does not overwrite a legitimate original setter
result. No unconditional successful-restoration claim is made.

The loader wrapper includes the accepted guard byte-exactly under renamed
symbols and retains both original try-locks/counter checks. Owner-only release
and active-state checks prevent a second real leave. If a failed profile end
already released the real locks, the group abort wrapper retries only folder
restoration. Failure cannot publish the old streamed envelope. New fixed stage
calls are observational; stripping them and the new prefix/tail reproduces the
complete old boundary/exporter source exactly.

The separate probe has schema coh-fresh-source-profile-probe-v2, exactly36keys,
fixed stage/refusal/folder/owner enums, booleans and counters0..65535. No identifier,
name, pointer, path, payload or hash is serialized. The supervisor precreates
and latches its0600 regular single-link file in a0700 owned parent before Map
launch. The source admits one initially empty handle using OPEN_EXISTING and
OPEN_REPARSE_POINT plus handle attributes/link count. All updates seek/write/

replaced pathname is never reopened or overwritten. The handle closes after a
terminal diagnostic, or through process cleanup if no attempt occurs. The
terminal file describes the first refusal/finished attempt, not process health.
All source probe mutations require the actual installation owner thread; a
foreign probe/hook call cannot race those plain fixed diagnostic fields. A probe
I/O failure may leave an unavailable or incomplete diagnostic.
