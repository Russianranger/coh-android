`retain_fresh_initial_observation.py` exports one bounded raw initial packet
only from the independently pinned, genuinely source-created fresh graphical
COHLOCAL/THORHERO fixture. The packet contains this disposable test character's
data. Existing backups and private user profiles never qualify. The generic
GROUPS run, owner records, receipts and logs remain private. The existing four
source-body retention gate is unchanged.

The tool accepts the same path/pin arguments as `retain_fresh_source_snapshot.py`,
including the independently obtained successful fixture receipt SHA, actual
private run/capture receipt pins, exact native build/PE inputs, native source
verification and the original source-admission receipt SHA. Set `--output` to a
new fixed basename `fresh-initial-observation`. No driver or profile selector is
accepted. The actual source admitter is repeated in a separate owned Python
process with the same original import closure; its complete immutable receipt
must equal the already admitted one. This launches no PG, Wine, client or server.

Before export, the private cleaned run must name the new fixed
`coh-local-initial-capture-build-v1` role. The exact post-cleanup optional binding
must be OBSERVED, match both retained and original native loan files, and bind
the same GROUPS packet, owner and DB/Map generations with one REQALLENTS. The
source envelope, original native/build/compile/verifier bytes, fixture/dump and
restore-copy bytes, run receipts and committed helper closure are rechecked.
No initial observation is substituted for full GROUPS/source admission.

The export contains exactly:

| File | Scope |
|---|---|
| `initial-update.bin` | Byte-exact observed raw ALLENTS packet, at most 4 MiB |
| `manifest.json` | Fixed sanitized packet SHA/length, bit/profile/cursor, shortcut ID/kind and update-prefix counters; genuine fixture/source pins and opaque source token |

No selected DBID, account/auth identity, connection, session, message or ownership
generation ID, GROUPS bytes, raw receipt, header, source envelope or log is in the
manifest. Shortcut IDs and the protocol full-update counter are parser metadata.
The raw packet remains explicitly approved disposable fixture data; sanitizing
its manifest does not sanitize or reinterpret those raw bytes.

The new output directory is 0700 and files are 0600. Bounded exclusive copies
flush, fsync, close and rehash source/target. Rebinding and final packet checks
precede an exclusively published, commit-last manifest. Both exported files and
source provenance are checked again after manifest I/O, before command success.
Every newly owned file
has its device/inode/uid recorded so rollback preserves replacements; cleanup
attempts are independent and preserve the primary error. On any refusal the
command exits nonzero and emits only a fixed failure code. Upload must require
this command's success and list the two exact paths; never upload the directory
on failure or upload generic private work/output directories.

Eleven offline `test_fresh_initial_retention.py` methods cover same-loan/scope
refusals, manifest privacy canaries, fixed destination and collisions, copy and
manifest late I/O/hash failures, replacement-safe rollback, private readmission
cleanup and fixed CLI failure output. These tests use synthetic packet bytes,
mock admission/manifest values and Linux file controls; no live token, native
capture, PG, Wine or graphical execution is produced.

The retained initial bytes are engineering input only. They confer no entity or
character-tail semantics, complete initial character, actor publication,
renderer, READY, received-character, full-update ACK, current-after-release or
world authority. The referenced source token remains an immutable source-side
point-in-time snapshot with its existing scope.
