# Immutable original-source snapshot admission

`admit_source_snapshot.py` closes the external source/run/fixture provenance
that the bounded inspector, logical packet pair and native verifier deliberately
do not grant. A successful receipt identifies **one immutable source snapshot**
and its exact same-call original GROUPS transaction. It does not claim that the
server still has that state after its quiet guard is released.

Run this only after the genuine fresh graphical fixture is independently admitted
and one actual original/native transaction succeeds in the owned hosted x86 job.
Run the new small native verifier and this admitter in that same job before the
private capture disappears. Do not rebuild a retained client/server producer or
repeat a capture merely to recover data that this first job could consume.

The runtime gate requires the real Linux x86_64 nonroot GitHub-hosted repository
branch/head identity and committed source bytes. Offline pure helper controls
return `source_generation_admitted:false` and never emit a positive token.
These environment checks are an execution-origin policy within the trusted owned
workflow, not cryptographic attestation of arbitrary caller-supplied environment
variables. The public receipt must retain the exact successful workflow/artifact
provenance; an unauthenticated receipt or SHA256 alone grants no authority.

The admitter requires all of these facts:

- Independently supplied pins for the exact fresh fixture, private actual capture
  receipt/run identity, compiled original observer, native receiver build receipt
  and native verification receipt. It repeats real fixture admission and hashes
  the retained creation evidence, whole PGDMP, literal account and actual private
  restore copy. Character identity comes only from the exact pinned ordinary-save
  backup. It is compared with actual selected ownership, never passed as a native
  DBID selection argument. Seeded rows or a newly created character during the
  restore/capture run are refused.
- Actual success, owned process/socket cleanup and unchanged input/runtime/binary
  guards. Current source hashes must match both producer receipts and committed
  Git blobs. The entire executed project Python import closure, explicit fixture
  admission helpers and compiler-derived native verifier C/header dependencies
  are checked against Git and rehashed before the receipt is emitted.
- The exact retained observer PE and native receiver ELF/build/source closure,
  actual copied MapServer and DbServer bytes, exact .34 database donor input and
  complete original control runtime inventory. Retained source revisions may
  differ from the orchestration revision only where current exact dependency
  bytes are independently admitted by the existing compile/native admission.
- A recomputed `capture_groups_transaction.pair` over the private source envelope,
  native receive/receipt and real source-created character. Exact logical packet
  bytes/bits, transport profile, selected source owner, Atlas identity, complete
  GROUPS/footer consumption and native socket cleanup must agree.
- E's exact `coh-source-snapshot-native-verification-v1` private receipt: all eight
  same-envelope payload hashes and native packet, executable bytes, current
  committed compiler-derived sources, release flags/libraries, exact five checks,
  strict fixed counters and the named96MiB aggregate limit. The verifier uses the
  existing complete `coh_scenecatalog_match` and native catalog/runtime/resource/
  raw-bounds/eligibility associations, including scalar definition comparisons.
  Its independently bounded resources parser can refuse an envelope above its
  32MiB native resource limit; no payload is trimmed or partially admitted.

A new private temporary file is fully flushed, fsynced and closed before an
exclusive no-replace link publishes the final receipt. Write/flush/fsync/close
failures independently close/unlink owned partial outputs and retain the primary
error; the public artifact step cannot collect a late-I/O partial positive.

The exclusive public `coh-immutable-source-snapshot-admission-v1` receipt exposes
an opaque SHA256 binding token, the orchestration/admitter source identity and
fixed scope flags only. Hash preimage inputs include private capture/run/native/
fixture/verifier/source dependencies; those inputs, counters, selected IDs,
account, cookie, raw envelope/packet/source bodies, paths and logs stay private.
CLI failures expose only the fixed `SOURCE_SNAPSHOT_REFUSED` status.

A successful source snapshot can admit the catalog, original GROUPS and captured
server-side resource associations at that captured generation. It keeps
post-release current lifetime, incremental updates, CLIENT cache/bounds/material/
LOD equivalence, actor identity, renderer publication, ACK and world authority
false. The source observation sequence number is not a runtime generation token.
No actual positive source snapshot or runtime claim is established by the host
test receipt in this directory.

The native verifier invocation is:

```sh
python3 native-android/engine/scenecatalog-server/check_source_snapshot_verifier.py \
  --capture PRIVATE/source.cohgtx --native-packet PRIVATE/native/groups.bin \
  --work NEW_PRIVATE_VERIFICATION --output NEW_PRIVATE_VERIFICATION/verification.json
```

The admitter requires `--private-output`, `--private-work`, `--fixture-directory`,
`--runtime`, `--control-fixture`, `--db-donor-apk`, `--compile-directory`,
`--native-capture`, `--native-build-receipt`, `--verification`,
`--verifier-executable`, `--output`, and independent `--capture-receipt-sha256`,
`--run-identity-sha256`, `--fixture-receipt-sha256`, `--compile-receipt-sha256`,
`--native-build-receipt-sha256`, `--verification-sha256` pins. Keep private argument
values/expanded failing commands out of public logs and upload only explicitly
reviewed public files. Generic private captures are never public artifacts.

Host controls: `python3 native-android/engine/scenecatalog-server/test_source_snapshot_admission.py`.
They exercise pure closure/refusal logic, every input/check/counter, release/build
shape, source drift, real temporary Git tracked-source ownership, mixed backup
reads, host refusal before file work, a real CLI private-canary refusal and late
flush/fsync/close rollback without a final receipt. They
run no PG/Wine/graphical service and mint no live token.
