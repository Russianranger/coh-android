`diagnose_source_cpu_sweep.c` owns one registered whole-file SourceBody at a time.
It derives every low-level request's canonical asset ID, full model name, whole
SHA and generation counter from the actual immutable Body lease; it checks the
returned CPU resource identity and every fixture material partition against the
retained index. Every additional source owner of the same pair is looked up and
checked against the same actual model/file identity. It uses the fixed source0/8,
v2,v3,v4,v5,v7 entries, without adding a policy mask or widening an ordinary gate.

This diagnostic intentionally keeps the file Body alive while sequential CPU
resources retire, so it can reuse the already validated index. It is not a new
production SourceBody retain API, not the ownership-transfer bridge, and not a
cache ready for app publication. Every resource/material pin retires before its
Body, and each Body retires before its loader/file. All391 cleanups report zero
pinned blobs. The graph stays alive through the last selector/Body retirement.

The fixture material supplier checks actual captured texture ID/name/triangle
partitions but supplies explicit fixture textures/material generation19. No real
texture lookup, CLIENT trick/composite/LOD, portal, reflection or stencil-render
state is inferred from these fixtures. Object-local positions/normals/UVs/indices
are qualified; root-instance transforms, selection, visibility and GPU publication
are separate consumers. No world or selected-character session is admitted.
