## Actionable integration findings

1. Original `clientcomm.c` processes optional embedded game commands after
   `entReceiveUpdate`. Exact message-end admission must follow their qualified
   processing or refusal. Do not copy the original early full-update ACK.
2. The renderer's receipt consumer relies on an authoritative upstream owner.
   Finite player-draw matrices and an entity tag do not establish that the matrix
   derives from the same actor pose. Require that relation before production
   publication; caller-supplied attestation bits cannot mint authority.
3. AuthServer's DB initialization can show a modal failure before exit, or return
   success with an empty failed connection pool and then wait indefinitely before
   listener startup. These are source-proven candidate explanations for alive/no
   listener, not the established historical cause. Investigate those boundaries
   independently of the already established receive-offset defect.
4. Native diagnostic aggregate memory remains 16,791,741 named bytes, with
   16,298,797 measured native-heap peak. These are diagnostic scopes, not production
   graph ownership, Python heap, Android process-tree RSS or a kernel memory cap.
   No device speedup is established by this continuation.
