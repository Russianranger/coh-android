This new runner owns one fresh ordinary encrypted Auth login and privately
consumes its actual shard1 grant through the opaque owner. Its new scope is
explicitly provisional: it requests the original development exception and
stops at one complete matching empty/unlocked DB character list. Normal
version/reference checksum, character creation/selection, Map and world
authority remain unadmitted. No grant, UID, cookie or DBID input is accepted.

The default and selected-grant activation scopes keep their original admission
paths. A new development_scope argument is mutually exclusive with
selected_scope and requires the exact new DevelopmentScope class, the exact
DbCandidate class and matching frozen candidate-generation pins. The new
driver's policy flag is explicit. It never subclasses or impersonates a
selected scope. The original service binaries, SQL/schema/profile defaults,
Auth-only fixture, crypto and ordinary native core remain unchanged.

Before any SQL/service startup the new runner compiles only its16 native probe
translation units and the existing exact21-source x64 zlib recipe. It reuses
the admitted retained x64 static OpenSSL library. Original zlib archive/tree/
blob/mode evidence is admitted before recovery; the private112-file derivative
contains the unchanged111 files and exactly the existing CMake patch. Windows
physical stat mode is not substituted for the admitted original Git modes.
The isolated project uses /MT, the existing ZLIB::ZLIB public interface and
x64 MSVC; it never configures CoX or rebuilds a server or OpenSSL. Source lists,
Release target properties, object inventory, AMD64 COFF header identities and PE
imports are admitted after compilation. COFF admission records header machine
and whole-file hash; it does not claim a full object parser. The bounded PE32+
parser requires only fixed platform DLLs and refuses delay imports; it does not
prove actual OS loader/export resolution. Build descendants belong to jobs;
logs stay private and only fixed build-stage/counter/hash metadata survives.

The distinct --platform-preflight native schema runs entropy, actual self-file
MD5 and WSA initialization/teardown with no owner, sockets or account input.
It runs before SQL startup. Successful preflight is not a DB-list result.

Only after that preflight does the new scope prepare normal disposable account,
128-byte user data and exact group1 membership. An empty nonce-owned HKCU key
uses the unchanged ClientProject derivation from the owned LocalDB nonce. Both
registry views must lack a preexisting nonce key; actual creation disposition
establishes ownership. No installation/version/checksum reference value is
written. Empty precreation changes the original getter branch to existing-key/
missing-value/NULL; this is labeled source inference, not an observed server
predicate. The original development lookup result remains NULL. The registry
owner uses the explicit fresh-host/exclusive nonce writer precondition, and
claims no atomic check/delete protection against unrelated same-user writers.

Auth/Db/SQL generations, copied PEs, registration/listener ownership, unchanged
runtime config and ClientProject, complete user data and exact normal membership
are checked before and after the native attempt, even on failure. Strict native
schema admission permits only fixed enums/Booleans/bounded counters and requires
one full matching list, exact terminal phases, no independent services, no
choice/handoff and complete native cleanup. Failure output is projected before
child cleanup; cleanup errors preserve a primary refusal/deadline.

Only the new development scope launches children with CREATE_SUSPENDED. Its
one-use launcher retains the exact Popen object; successful job assignment
precedes any primary-thread resume. A separately source-qualified helper binds
the retained process handle/PID/start generation and exactly one owned primary
thread across two bounded snapshots, verifies the opened thread's ID/owner/start
generation again immediately before ResumeThread, and requires a previous
suspend count of exactly one. Ordinary refusals and late close failures are
one-shot; the owned child/job is terminated rather than resumed again. All new
build, native probe and Auth/Db service launches use this path. The helper's
source, controls and source-only proof are explicitly pinned before its dynamic
import. It accepts no raw PID/thread selector and exports fixed projections.

The new development scope also uses stronger job completion: termination is
followed by a bounded exact empty descendant inventory while the job handle
is retained, then root exit and handle closure. The accepted default and
selected-grant job behavior is unchanged. Registry cleanup requires this
observed completion for every new service job and for an attempted native
child, plus the common service teardown result. Missing observations refuse
that precondition. Each job also latches its exact child only after a successful
assignment; a refused assignment cannot turn an empty never-assigned job into
a completion proof. Pending jobs with no child have a distinct empty-inventory
close path. A mismatched child is never waited on or killed as owned. Direct
child kill/wait is attempted independently even if job APIs fail. Fallback
closure retains a handle on refusal and preserves the first stop/query error.
The common intermediate receipt stays inside the private
build directory; the public final receipt is written only after these gates.

Service teardown completes before registry cleanup. Only owned empty
nonce keys and an owned newly created empty parent may be removed, with both
views absent and handles closed. Candidate/source admission and removal of the
private build/crypto-client temporary files are checked separately afterward.
Any failure blocks success. A native request with unavailable failure output
stays UNAVAILABLE rather than acquiring an invented DB-login result.
