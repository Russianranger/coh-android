# Bounded monitor envelope and observation labels

This standalone adapter prepares an uncompressed, untyped ServerMonitor version request and incrementally assembles opaque source TCP frames. It has no socket, JNI, service, credentials, NetLink pump, crypto defaults or live permit. Existing accepted client/network paths are untouched.

`coh_monitor_request` uses the existing `coh_protocol_write_pack` kernel for command10, or source old-profile command15 when legacy mode is explicitly selected. It emits no monitor CONNECT or application body. It supports no cookieSend/cookieEcho or byte-aligned compressed-command profile. The future network5 experiment must select legacy0 and verify the actual negotiated profile; it must not infer profile from packet contents.

`coh_monitor_stream_feed` buffers at most 1,472 bytes and consumes at most one complete frame per call. The source TCP header's first clear little-endian U32 is logical **bit length**, not byte count or an AuthServer inclusive-U16 length. Source `pktGetTcp` and `pktGetTcpAsync` apply `blowfishPad(ceil(bits/8))` even to clear frames. The bounded assembler uses the same length convention and the existing native frame decoder's minimum105-bit subset. Invalid/oversized lengths poison until reset. Coalesced remaining bytes are retained by the caller through consumed count; incomplete/malformed input never publishes a frame. Frames are copied to caller-owned fixed storage, so no borrowed view survives another feed. Partial state must be reset on EOF, cancellation or a different owner generation. State, complete declared input, consumed-count storage and output must be pairwise disjoint; pointer-range overflow and all known overlaps refuse before any write. Request output and bit-count spans are checked likewise. Negative controls cover all six stream span pairs and overflow, preserving state/output/count on refusal.

Assembly does not establish checksum, encryption, command validity or handshake completion. Pass each complete frame to the existing independently qualified native frame decoder with its actual negotiated version, encryption/key and connect flags. Existing AuthServer framing cannot substitute. The native NetLink socket owner and DB session are UDP; this adapter does not upgrade them to TCP. In particular original TCP compression uses a persistent streaming dictionary even for unordered packets, while existing native UDP decoding chooses streaming based on ordered delivery. **TCP streaming compression remains unqualified** and must not silently reuse unordered UDP decompression. The narrow version response profile must explicitly reject unsupported compressed/typed/sibling handling until independently qualified.

The local qualifier reuses exact Git versions of existing native protocol, frame and Blowfish kernels, without copying or changing their implementation in the repository. It also executes the exact original `blowfishPad` over every logical length from105 through11,776 bits. Release and ASan/UBSan each pass35,338 checks: packed request profiles, incremental20-byte frame schedules with every send cap1–20, atomic output preservation, native CRC/frame decoding after assembly, three coalesced frames, bad/overflow/undersize declarations, poison/reset, corrupted stream state and source padding equality. LeakSanitizer is disabled. These are synthetic byte deliveries, not original socket execution or actual TCP segmentation acceptance. The existing accepted crypto functions are reused; no new encryption negotiation is claimed.

## Handshake and ownership labels

Original `netConnectEx` resets the link to network0 for CONNECT, sends packed connect ID and requested version, then applies the requested version. The four control steps are client CONNECT(1), server ACK(2), client ACK(3), server final ACK_ACK(4). Encrypted ACK processing derives receive decryption before final acknowledgement; send encryption activates after the final. `netAckConnect` does not echo the connect ID, so it cannot be treated as remote process authentication. Original retry/fallback logic can lower requested version after repeated disconnects. The narrow metadata profile requires requested and negotiated network5 with no implicit fallback, plus an explicit encryption requirement; a clear server ACK cannot satisfy a required encrypted profile. This is observation matching, not a new wire handshake implementation.

`monitor_channel_contract.match_metadata` compares before/after process PID, process-start digest, binary digest and owner generation; server-side listener/connection IPv4 loopback labels and port6996; peer endpoint/port; and the exact four timestamped control observations in a bounded15-second metadata window. A changed process lifetime, peer/profile, missing/reordered final acknowledgement, downgrade, unsupported protocol or mismatched generation is refused. The time bound and loopback restriction are experiment policy, not original protocol TTL or security guarantees.

All records are supplied labels. Even a complete matching result leaves actual process ownership, socket ownership, NetLink handshake verification and live request permission false. There is no API here to create a trusted OS receipt, open a socket or authorize a request. A future reviewed observer must independently establish process ownership/start identity, listener and connection PID association, socket lifetime/generation, full valid control parsing, crypto requirements and cleanup. The original wildcard monitor listener must not be treated as isolated without observed enforcement. Version payload/first-lookup admission remains separate.

Three Python suites cover immutable false-permit results, PID/start/binary/generation/liveness/endpoint mismatch, control ordering and time, network fallback and encryption downgrade refusal. Exact original function/source and reused native dependency hashes plus both native runs are retained in `../evidence/monitor-envelope-contract-20261017/native-host.json`. No Windows/Android/Thor or server qualification is claimed.
