This new nonshipping main is for the separately authorized provisional
Auth-to-DB-list experiment. A private stdin pipe supplies one account and
password. The frozen opaque owner performs the genuine encrypted Auth login,
selects the registered shard, privately consumes its actual grant once, and
uses the ordinary encrypted DB session. The scope stops at exactly one fully
parsed matching empty and unlocked character list. It offers no creation,
selection, DBID, Map, actor or current-world authority.

The owner requests the original development exception. That is explicit
provisional policy. The probe never reports the server's internal predicate
as observed: its fixed flags say development use is source inference only,
normal version and checksum reference remain unadmitted, and a graceful peer
disconnect has not been acknowledged. The actual owner cancels the DB session
before destruction; its final diagnostic phase is CANCELLED, while Auth is
CLOSED. Those phases must match before the new main can pass.

The Windows branch obtains a fresh nonzero 32-bit transport label from retained
OpenSSL entropy. It measures the MD5 of this executable file for the ordinary
wire field. The file comes from `GetModuleFileNameW`; a read-only handle excludes
write/delete sharing and opens a reparse object for rejection. Reads are bounded
to 16MiB and the file's initial length. The label, digest, path, file bytes,
credentials, grant, UID, cookie and player names are never printed. Caller
credentials/configuration are wiped on every exit. The digest is an actual
probe-file measurement, not a matching or approved reference checksum.

The main destroys its owner before independently finishing the new UDP and
retained TCP adapters. Successful DB-list output also requires exactly one UDP
socket created and closed, no retained handles or close/WSA-cleanup failures,
and complete local buffer cleanup. Any late cleanup failure prevents success.
Output contains only fixed enums, bounded-by-owner counters and Boolean or
0/1 diagnostic fields. The future owned host driver must independently admit
its exact schema/ranges, PE/source provenance, process generations and teardown.

The fixed `probe_stage` values identify input (0), TCP initialization (1), TCP
limits (2), UDP initialization (3), entropy (4), self-file digest (5), owner
creation (6), begin (7), service (8), completed-owner result (9), or platform
preflight completion (10). They add no private identifiers to failure output.

`--platform-preflight` has a separate fixed schema. It performs entropy,
self-file hashing and WSA startup/cleanup, then wipes its configuration. It
creates no sockets or owner and requires zero UDP sockets. This provides a
future Windows compile/API smoke before any original SQL/service startup. A
preflight result cannot qualify a DB login or character list.

`test_db_development_probe.py` controls the platform and owner interfaces rather
than running the actual owner, crypto or Windows code. Its 48 scenarios cover
the private main's exact completion/counter/policy gates, source-shaped final
phases, caller-buffer wiping, controller-before-transport cleanup order, and
late failures. It also checks 12 malformed private-input/port cases and a
separate synthetic no-owner preflight. The two new methods run optimized and
ASan/UBSan versions of the scenario shell. The actual owner has its separate
Worker C qualification; that qualifier is not replayed here.

The actual Windows header/API branch, native link with recovered exact x64
zlib, actual fresh Auth grant, real DB login, server development predicate,
matching real character list and Map remain unqualified by these host checks.
No server binary/profile or ordinary Auth/DB/session/transport source changes
are part of this main.
