# Owned DbServer version observation: payload-only source contract

The original ServerMonitor request/response command is **10**, derived from `COMM_MAX_CMD=2` plus the original ServerMonitor enum ordering. The DbServer listener port is **6996**. `svrMonRequest` sends this application command with no body fields, then flushes the link. These values describe the original NetLink protocol; they are not a raw TCP frame. No socket or request transmission is implemented here.

`DBServer/src/svrmoncomm.c::svrMonHandleClientMsg` requires a client object created by the transport callback. Its REQUESTVERSION branch does not test `svrmon_ready`. It creates a response with the same command, sends `getCompatibleGameVersion()` first and `getExecutablePatchVersion("CoH Server")` second, then sends and flushes. The branch has no account, character or command-execution operation. Application lookup can initialize the original version cache. Original functions are source-audited, not executed by this component.

The ordinary `DBSVRMON_CONNECT` exchange sends protocol major/minor `20110804`. Success sets `svrmon_ready` and `full_update`, initiating unrelated container/statistics publication. The narrow future observer should send only REQUESTVERSION after separately qualified transport establishment; it must not send monitor CONNECT, player subscription, EXEC or relay commands. Current source shows no application authentication/readiness gate before REQUESTVERSION, which does not establish trustworthy process or channel ownership. The original `svrMonInit` calls `netInit(...,0,6996)`, so an owned loopback listener cannot be assumed from the original listener declaration. A future disposable experiment must separately enforce and observe listener isolation. Nothing here starts or reconfigures that listener.

For non-debug packets, original `pktSendString` calls `bsWriteString`. That writer emits NUL-terminated octets at the current bit cursor, preserving its bit offset. `version_observation_contract.decode_body` accepts only a caller-supplied, already decoded command-10 application body with an explicit start offset (0–7), exact bit count and non-debug mode. It reads exactly two nonempty printable ASCII strings of at most 99 bytes each and rejects truncation, extra body data, unsupported mode and oversized input. This is a deliberately bounded experiment subset; it does not reproduce the original reader's growable buffer or `strcpy` behavior. Fixture construction independently places each octet's bits at every offset; no original bitstream writer/reader execution or transport-oracle equality is claimed.

The immutable request and decoded-body records leave transport qualification, actual process version verification, live channel ownership and deployment admission false. Generation digests are supplied metadata labels; they are not authenticated provenance. No historical login receipt or body string can mint a live session or approve normal-version policy.

Four host suites pass: six exact source blobs and function/branch identities; 792 valid offset/length cases; all byte truncations at all offsets plus extra data, unsupported mode and bound controls; and a version-only loopback metadata declaration that rejects other commands/ports. No C/C++ source function, Windows process, server, Android application or Thor was executed for this standalone Python decoder, so ASan/UBSan and Android acceptance do not apply. Exact audit and host source hashes are retained in `../evidence/version-observation-contract-20261017/source-audit.json`.

A live observer still requires qualified NetLink TCP establishment, application command extraction, compression/debug handling, bounded packet ownership and cleanup, an actually owned isolated DbServer process/lifetime, and source-qualified listener association. Its received two strings must then be bound to the exact process and the version-provider input shape in `DB-CHECKSUM-BUILD-ONLY.md`. A normal-version claim additionally needs the actual nondevelopment provider result, empty override and correct first-lookup ordering; a merely parsed version label does not provide that evidence.
