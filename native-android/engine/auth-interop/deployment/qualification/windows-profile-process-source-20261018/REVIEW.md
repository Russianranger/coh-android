# Windows profile/process source freeze

This records a source-only review, not compilation or Windows qualification.
The coordinator owns integration and the first new inert-only workflow.

The final helper uses a dedicated process, a native wipeable password buffer,
an exact newly created account SID, a protected private journal and new private
window station/desktop. It creates the fixed inert process suspended, retains
its returned process/thread handles, verifies identity, assigns the owned job
and attempts one checked resume. Independent cleanup preserves the first
failure and refuses complete cleanup until process/job/handle/GUI/hive/profile/
account/file gates close. Unobserved ownership is quarantined.

association restoration and same-SID profile/account cleanup. Worker F read

receipts. Both reviewers and E executed no compiler, tests or Windows APIs.

The prior 3e97f891 helper was the initial review freeze. D and F independently
found that attempted-but-unbound account creation could be called absent
without requery, allowing intent retirement. The successor requires actual
exact-name absence and a no-launch state, or retains the journal and never
deletes an unbound account. It also requires a fixed local drive instead of
accepting a mapped drive letter. The test source adds absent/present unbound
account model cases; none has run. No separately retained prior source copy
existed in E's approved scratch source set; this record preserves its hash and
finding history without pretending a historical runtime or fabricating bytes.

The new build recipe uses installed Framework64 csc only, with explicit
framework references, no implicit csc.rsp and a new asInvoker/uiAccess=false
manifest. It compiles three explicit entry points and runs none. No csproj,
NuGet/package restore, installer, external compiler, Auth/Db/Map/service or
accepted17 test suite is needed or authorized by this record. The recipe and
manifest were read as text/XML only; PowerShell and csc have not run. Root must
review the proposed build definitions before any compilation or testing.

Generated credentials never enter managed immutable strings, arguments,
environment variables, logs or public output. Usernames, SIDs, profile paths
and raw owner journals remain private. Only the fixed public receipt projection
is eligible for the future runtime's public output. A watchdog/crash supplies
no cleanup claim; implicit profile loading and synchronous native calls have
no strict whole-API deadline guarantee. Full compiler/CLR/loaded mapping and
application/service/world authority remain outside this source review.
