# Original group bounds numerical adapter

`coh_group_bounds_compute` implements the numerical part of original `Common/group/group.c` functions `groupGetBoundsTransformed`, `groupGetBoundsMinMax`, and `groupSetBounds`. It accepts an already admitted model box and immediate children with already admitted bounds and original column-major 4-by-3 transforms. It does not traverse the graph or acquire assets. Definitions must be processed bottom-up by a separate owner with generation and resource checks.

The original policy is deliberately retained: a transformed child box uses the child's unscaled radius when all three box dimensions are at least its diameter; the final parent radius can be replaced by the maximum transformed child-center distance plus child radius, then is clamped to the model half diagonal. A volume replaces the accumulated box and starts its vertical range at zero. These rules differ from a generic enclosing sphere or scale-corrected box policy.

The kernel makes no allocations and limits each of its two child passes to 262,144 entries. Each non-null child costs eight corner transforms, plus at most two center transforms. The caller owns and charges the immutable input arrays; the largest input array is `262144 * sizeof(CohGroupBoundsChild)` bytes. Cancellation is checked per entry and immediately before output publication. Refusal leaves output unchanged. Input boxes must be ordered, radii and volume dimensions nonnegative, and active values and computed results finite. These explicit admission restrictions reject malformed/nonfinite/overflow inputs beyond the source's unguarded numerical domain.

CLIENT `pre_alloc` returns without updating the source bounds. This adapter refuses that case rather than inventing future-object geometry. It also omits source diagnostic `rad_count`/`box_count` global accumulation and the unrelated `bounds_valid` return value. Numerical success does not set bounds validity, prove recursive ordering, admit a model, or authorize world publication.

`check_group_bounds.py --output receipt.json --sanitize` verifies pinned original source, extracts the original functions and `mulVecMat4` unchanged into a small fixture-owner shim, and compares native output byte-for-byte on deterministic fixtures. The source reference is a host reference, not sanitized original MapServer execution. Native fixtures and malformed/cancellation rollback controls run separately in release, ASan and UBSan modes. The supplied checker disables floating-point contraction (`-ffp-contract=off`); consuming targets must preserve that setting and avoid fast-math reassociation for byte-level source parity. LeakSanitizer is disabled because this host sandbox cannot inspect the required process task directory; the numerical kernel has no heap calls. This does not qualify Android execution or actual world resource admission.

# Remaining CLIENT LOD and material prerequisites

The saved definition's five LOD floats and SERVER resource observation are insufficient to reproduce the client's effective visibility and material state. In `Game/src/group/groupnetrecv.c`, `receiveDef` reads those floats, then calls `getGeo`, which calls `groupModelFind` and `groupSetTrickFlags`, before `groupSetBounds`.

`Common/group/groupfileload.c:groupSetTrickFlags` copies model trick distances/scale/shadow values and applies group flags. Its CLIENT branch replaces near distances from the first `Model.lod_info` entry and far distances from the last entry, and can load or generate auto-LOD models. It finally calls `groupSetLodValues`: file far/fade override only when no trick owns them; file scale overrides independently; zero scale becomes one; absent model far/fade may derive from model half diagonal and shadow distance. The near values remain trick-owned. A later adapter must retain those exact provenance and precedence distinctions, plus inherited draw/material state; this bounds kernel establishes none of them. Protected CLIENT source/assets remain read-only.
