# Immutable costume candidate and unavailable runtime admission

`coh_costume_owner_candidate` joins the existing COHCDI1 full-slot importer with
the existing COHBW1 complete ordered BodyPart observation format. It preserves
every supplied witness byte, nullable versus empty strings, signed raw bone and
cost fields, source row order, original callback index, one/two-bone values and
U8 DontClear. It copies the entire witness and owns the existing immutable
dictionary allocation, including every string/palette slot, hole and key.
The exact original BodyType enum, definition and nine-row source table are
retained as data; they are regenerated/compared against pinned original source
and the unchanged original `getBodyTypeCount()` is executed by the checker.

The factory checks the complete original witness route shape and zero reserved
generation/authority fields. It compares whole-input SHA256, expected source,
build, profile/run labels, declared row count, import count and bodytype count.
Profile/run label coherence is an integrity condition only. It does **not**
establish that these rows generated these dictionary slots, ran in one actual
executable, came from the selected source process, or belong to a current Map
generation. A matching count is never proof of a complete row/slot association.

There is no active-owner constructor, caller verified flag or hash-based
promotion. `coh_costume_owner_query` is the narrow stage-41 consumer interface:
missing owner refuses NOT_FOUND, stale declared generation/retired owner refuses
STATE, and a coherent immutable candidate refuses UNSUPPORTED. Its output
counts remain unchanged. An exact packet descriptor with actual loan/session/
source/generation billing keys is necessary but cannot create a source lease.
The descriptor is inspected synchronously and no packet pointer is retained.

The missing prerequisite is a separately qualified producer lease binding the
actual loaded BodyPart rows, complete costume tables, runtime source executable,
selected profile, initialization/reload generation and this exact Map/packet
loan. The existing nonshipping witness deliberately cannot supply that lease.
Target compile/preflight receipts cannot supply it either. Consequently **no
live default count, body acceptance, indexed-string resolution, character,
actor, READY, RECEIVED_CHARACTER or application ACK is enabled here**.

Offline views use sixteen fixed lease slots in the actual candidate owner.
They pin the owned rows/dictionary. Retire blocks new leases and runtime queries
while existing offline consumers remain valid. Destroy and replacement refuse
while any data lease is outstanding. The last explicit release permits owner
destruction; no pointer or generation label silently survives replacement.
Leases are zero-initialized before borrow and unchanged except by this API;
they are bookkeeping tokens, not security capabilities. Calls require a serial
coordinator and valid returned opaque owners. There is no concurrent mutation
or forged-pointer safety claim. A read-only overlap guard lets the stage-41
consumer reject output aliases with owner/witness/dictionary/static definitions
and every actual active lease token. New leases/views cannot overlap an active
token even partially; release permits only its own original token storage
before diagnostics mutate any storage.

All allocation/callback reservations precede either digest and all allocations.
The unchanged 8 MiB importer ceiling bounds the complete named aggregate:
current/old/external retained resources, new owner plus complete witness,
maximum 4 MiB dictionary, actual temporary slots, both original input spans,
provider/context/scratch, output/control metadata, the full supported sixteen
external token/view control spans, exact static definitions and
two separate 16 KiB native stack reserves. Caller `retained` must include every
other live owner and its actual dependency leases; this is not a concrete
process-wide parent-ledger adapter. No generic ticket is fabricated. Source
owners are absent, not assigned zero-cost fictional leases. The fixture's
two-row candidate owns 1,365 bytes, with a 4,249,484-byte named peak reservation.
These values are neither process RSS/PSS nor actual Thor peaks.

The focused synthetic candidate fixture exercises full indexed string/key/hole
decoding through the **existing** costume parser in both packet width modes,
then wipes original inputs and repeats through retained immutable data. It also
tests maximum 29 rows/259-byte strings, full witness truncation/byte mutation,
missing/stale bindings, aliases/endpoints, all three real calloc failures,
both digest faults, exact/one-byte-short budgets, overflow, fixed lease
exhaustion, stale duplicate releases, retire/replacement rollback and 128 full
load/borrow/retire/release/destroy cycles. Active lease storage addresses are
retained until release, so a by-value copy refuses both before and after the
original token releases and cannot retire another consumer's borrow.
Only the standalone source-shaped
dictionary parser is invoked; these synthetic slots do not become live inputs.

```sh
flock /tmp/coh-cycle-build.lock python3 \
  native-android/engine/character-dictionary/check_costume_owner.py \
  --source-root . --work /tmp/fresh-costume-owner \
  --output /tmp/costume-owner.json
```

Release, ASan and UBSan run sequentially. LeakSanitizer is explicitly disabled
under the inherited host restriction; actual owned calloc/free accounting
balances after the three injected allocation failures, without a leak-proof
or external crypto/sanitizer/stack-closure claim. No Android build/execution,
source-process deployment, runtime catalog capture or physical test occurs.
