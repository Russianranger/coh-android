## Shared-set source state cannot be guessed from allocated flags

The exact donor has27 allocated Shared rows but only26 references reached by
the finalized category/local-set traversal; the unreachable row is
`N_Tutorial_Powers.Atlas_Normal_VisionPhase`. The source-qualified native owner
models an initially empty first call (26) or a second append against the same
immutable dictionary family (52), preserving reference order and repeats.

Original `load_PowerDictionary` calls `powerdict_FindSharedPowersets` after both
the shared-memory hit and parser-load fallback, without clearing the global
list. Its source load flags differ on SERVER. `character_ReceivePowers` copies
the first `g_numSharedPowersets` build0 pointers into builds1..7 and omits these
entries from their wire loops. A source-current count is therefore a framing
prerequisite, not an optional semantic hint. Choosing26 because the donor is
available, choosing27 from allocated flags or choosing52 from a hypothetical
reload would fabricate a runtime branch. Cross-dictionary old pointers also
require a different lifetime owner and are intentionally refused.

## Dynamic ordering requires actual trackers

Original `groupDynBuildBreakableList` clears the count, then traverses ascending
non-null root reference slots through `groupProcessDefTracker`. For each actual
tracker, `findBreakable` resets its dynamic ID; it may lazy-load its definition,
appends that **tracker** when `breakable` is set, and returns `child_breakable`
to decide whether recursion continues. Only then does the traversal call
`trackerOpen` and visit ascending actual `tracker.entries`.

`trackerOpen` immediately returns when entries already exist. Otherwise it
preloads parent/current/child definitions and creates entries from the then-live
definition array. Thus a complete definition DAG walk, even with matrices and
all repeats, is not proof of actual tracker membership. Lazy loading and prior
tracker state must not be silently modeled as an ideal fresh tree.

The reusable runtime occurrence walker preserves root-slot/child-entry preorder,
all DAG occurrences, matrices and ordinal/parent identity. It deliberately has
no dynamic pruning predicate. Runtime snapshot named breakable flags exist for
external pre-allocated definitions; ordinary catalog wire rows do not include
those flags. Public raw60-byte bounds prefixes are explicitly ABI-opaque and
cover selected public rows: interpreting their bits or deriving Health property
flags cannot establish all actual tracker entries/current dynamic order.

A useful source witness must associate every zero-based `dyn_groups` index with
its actual tracker occurrence (root slot and actual child path), current
definition identity, source world matrix, the exact list count, reset/build/map
generation and `DynGroupStatus` ABI. Source world ID is index+1. It must be
captured coherently with the scene and initial packet; a count-only observation
does not establish this mapping. A is auditing the isolated source observer
design; C does not alter the existing snapshot sink or PE/source overlay.

Original full update writes the full marker and zipped
`dyn_group_count * sizeof(DynGroupStatus)` bytes; the client rebuilds its own
list before comparing the received byte-derived count. The native diagnostic
validates exact inflated length, stream end and ordered deltas but keeps
`world_ownership_verified=0`. Inspecting full-body length can inform a **syntax
diagnostic**; it cannot supply the missing ordered world owner.
