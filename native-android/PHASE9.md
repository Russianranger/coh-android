# Phase 9: bounded source world and camera gate

This phase implements an isolated native Android source-world and camera probe, package `org.coh.worldprobe`. Version `0.1.0-phase9` passed host and Android13 emulator checks, then failed the Thor transform diagnostic. Version `0.1.1-phase9` preserves source operation order explicitly in the GPU shader and passed host, Android13 emulator and physical AYN Thor qualification. The original [scene recovery receipt](evidence/phase9/scene-recovery.json) preserves the source deconstruction and authentic geometry/texture recovery.

## Camera and qualification contract

The unchanged source bodies of `gfxSetViewMat`, `rdrFixMat`, `rdrSetupPerspectiveProjection` and `rdrSetupFrustum` are recovered and exercised by the host oracle. The original view conversion transposes the camera rotation and mirrors X using `diag(-1,+1,+1)` before computing view translation. Six bounded test cameras use explicit controlled Pos/PYR, vertical FOV, aspect and near/far values. The original gameplay FOV adjustment above 4:3 is not selected. These inputs are test cameras, not captured live gameplay state.

The host oracles execute unchanged source degree conversion, matrix construction/composition, view conversion, perspective and geometry-expansion kernels under documented minimal compatibility wrappers. Independent references verify world positions, unnormalized eye normals, eye/clip-space outputs and selected material arithmetic. GPU transform feedback and pixel checks require useful geometry coverage, source culling and depth behavior. Five controlled clip-space witnesses test both opaque depth orders, clockwise/back-face culling, a near-plane crossing and far-plane rejection; their diagnostic vertices are explicitly separate from original map geometry. A full original scene sorter is not established by one branch; source pointer tie comparisons need an explicit portable policy before broader sorting qualification.

The implemented probe distinguishes passing render checks from completed lifecycle qualification. After resize/recreation checks pass but before background recovery, it displays **RENDER CHECKS PASSED — Background/return check required**. A green gate requires actual two-axis resize, successful Surface recreation, recorded pause/stop and destruction callbacks, then resume, a new current Surface generation, and a successful nonobsolete native result with matching inputs. Device instructions and the emulator gate explicitly use Home for this sequence. Sticky active failures cannot be erased by later stale successes. Export remains an immutable foreground snapshot; callbacks caused by the subsequent file picker cannot retroactively satisfy that exported snapshot. Existing Phase 8 UI remains unchanged.

The user accepted the remaining Phase 8 Home/return requirement on October 13 and directed implementation of this successor gate; the acceptance receipt distinguishes confirmation from measured events. This bounded implementation makes no full Atlas load, camera collision, playable client, networking, FPS, startup or zoning claim.

## Implementation and host evidence

Three bounded assets drive the isolated package: `world.bin` stores original Pos/PYR inputs, controlled camera inputs, canonical meshes and authentic RGBA textures; `world-reference.bin` stores comparison matrices/geometry; `material-reference.bin` stores twelve independent shader cases. Runtime rendering computes its matrices from source inputs. Golden matrices and geometry are comparison data and do not drive the preview or actual-image path.

Original source traversal composes view with each parent/child matrix before transforming vertices. The native implementation retains that binary32 operation order and the original camera X mirror. The [unchanged source oracle](evidence/phase9/original-world-parity.json) passes 40,744 float components across fifteen functions; the independent reference passes 40,680 components. The [geometry oracle](evidence/phase9/original-delta-parity.json) checks 3,124 original scalar elements byte-exact. The [host proof](evidence/phase9/host-world-proof.json) passes 40,320 components and 6,545 ASan/UBSan checks, including 6,000 mutations. These tests use documented minimal source compatibility wrappers, select the original `_WIN64` float-libm trig branch, and do not execute the original 32-bit x87 trig branch or the full Game.

The new GLES3 renderer checks 39,936 GPU components per context (world positions, unnormalized eye normals, eye positions, homogeneous clip coordinates), six perspective images, useful coverage for each partition, twelve material cases, and five labeled depth/culling/near/far diagnostics. It retains a 1e-4 absolute transform tolerance, two RGBA byte units and a two-pixel triangle guard. World sampling uses linear mip-zero filtering; analytic shader cases and exact window transfer use nearest sampling. Lighting is controlled neutral ambient 0.25 with zero diffuse/specular; source Ambient/TexSwap/LOD metadata is retained without claiming the full Atlas lighting or cubemap pipeline.

Each check creates/releases two EGL contexts and presents two bounded 45-frame camera previews. The [host Mesa smoke receipt](evidence/phase9/host-renderer-smoke.json) passes all renderer checks in a Linux pbuffer harness, with zero errors and mismatches; it is separate from Android and Thor qualification. The [UI host checks](evidence/phase9/ui-host-checks.json) verify sixteen lifecycle cases. The final NDK build preserves warnings as errors. An explicit const qualification fixed the [first NDK compilation failure](evidence/phase9/first-ndk-build-failure.json) without changing arithmetic, operation order, asset bytes or comparison tolerances; source math, sanitizer and host-renderer checks were repeated successfully.

Original payload bytes and complete metadata match the qualified 0.1.1 APK. The former one-step world-coordinate failure is resolved on the actual Thor. This remains the bounded scene/camera/material gate; full Atlas loading, physics, gameplay, networking and performance are separate.

The [Thor 0.1.0 failure](evidence/phase9/thor-transform-failure-0.1.0.json) records four consistent failures before pixel, material or preview tests. It supports the rounding-order explanation without claiming captured Adreno instructions. The portable [regression checker](tools/world_fixture/gpu_arithmetic_check.py) executes in CI and retains strict source order, references and tolerance.

The [host arithmetic matrix](evidence/phase9/host-shader-arithmetic-matrix.json) verifies all four paths with two contexts each; it is separate from Android and Thor execution.
