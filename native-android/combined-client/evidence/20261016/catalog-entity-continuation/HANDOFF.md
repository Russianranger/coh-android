## Scene catalog and graph progress

`engine/scenecatalog` exports complete records through the **unchanged original
`sendDef`** and original definition/reference checksum functions. The envelope
preserves actual file indices, filenames/bounds checksums, sparse definition
slots, null holes, allocated tombstones, original record bytes and a caller-owned
asset generation. Producer traversal, output and record limits are explicit;
the original trusted packet allocator is not claimed to have a hard heap cap.

Allocation-free preflight checks bounded shape/counts/name CRCs. Full load uses
the shared transactional scenegraph definition decoder, owns all retained
strings/children/metadata, and retains the previous catalog on any failure.
The `CohSgImportFn` adapter binds exact filename, checksum and generation. Initial
GROUPS matching checks file count, definition/reference CRCs and active roots;
complete graph application remains the independent transform, asset, reference,
cycle and final checksum gate. CRCs are not payload or asset authentication.

A synthetic original-producer stress catalog has **508 files, 12,192 allocated
definitions, 36,567 child links and 33 roots**. It owns **26,276,931 bytes** on
64-bit host; replacement peaks at **52,553,862 bytes** within the module's
32/64 MiB ownership policy. These are fixture results, not captured Atlas data.
An oversized candidate rejects transactionally. The existing graph admission
caps remain **4,096 definitions / 16,384 children** and explicitly reject a
larger prepared catalog. No incomplete graph is published as a valid world.

Simply increasing graph caps retains quadratic insertion and linear name
resolution. Reserving 65,536 current definition structures alone exceeds the
32 MiB graph ownership limit. The next graph implementation needs counted
dynamic arrays, indexes for file/slot, roots and case-folded names, bounded
off-stack traversal, and an aggregate preparation budget covering retained
catalog, borrowed input, old graph, candidate and scratch. Current per-module
limits are not a whole-process memory ceiling. Preserve depth-128/cycle,
checksum, generation, allocation-failure and rollback controls.

The optional **NONSHIPPING** `engine/scenecatalog-server` overlay makes export
callable after normal-map `groupLoadMap` and `dbSetupMap`, before
`dbReadyForPlayers`. It preserves existing startup progress marks and unchanged
original group-network source bytes. It is excluded from the standard build and
shipping runtime. Staging reconstructs the exact certified-animation prerequisite
and checks inherited output hashes, aliases/links, unique anchors and repeated
staging. Its Win32 sink is disabled unless both explicit output/generation
environment values are admitted. Under an explicit private/exclusive parent and
stable snapshot contract it stages create-new output, bounds bytes, flushes and
closes, then renames without replacement. Failure removes only its own partial;
reports contain fixed numeric fields. No persistence/network/update hook,
runtime deployment or server-exit action was added.

**Actual deployment and capture remain open.** The real Thor server's matching
saved-definition catalog and imported geometry/material provenance are not
available in this environment. Offline `.bounds` names/bounds and subset text
parsers cannot reconstruct the original loader's slot/import/stub/rename order.

## Entity and authentication progress

`coh_ent_list` stages complete supported entity-list substructures atomically in
a caller-owned workspace (150,528 bytes on host), with at most 256 declared
slots. It preserves original modulo-32-bit delta semantics, including descending
append passes and the canonical final sentinel. It rejects duplicates, unknown
slots, stale generations and inconsistent selected DBID/self ownership across
the complete bounded table. Reader, table and receipt commit together. A list
without self establishes no player authority. Existing deletion ordering and
position/orientation/sequencer inspection remain preserved.

Fixtures compose unchanged original entity component producers; they do not run
the complete original `sendEntity`/`entSendUpdate`. Required appearance/netfx,
character/global/control/full-update tails remain bounded unsupported stages.
No renderable player, preview-derived authority, READY, RECEIVED_CHARACTER or
full-update acknowledgement was added.

Real encrypted AuthServer login remains **deployment-blocked**. No accessible
AuthServer executable/process, Windows compatibility runtime, SQL/ODBC service
or driver/configuration, authorized endpoint or disposable account was found in
the fresh environment. Unknown loopback listeners were not treated as auth or
probed. Auth/session implementation bytes were unchanged. Existing qualification
remains 2,147 policy checks across host/sanitizers/Android 13, 26 unchanged-source
cache/checksum checks and 23 sanitized TCP lifecycle checks; none proves a real
login. The documented original checksum defect was not bypassed. A matching
authorized AuthServer–DbServer–MapServer deployment, account schema/registration,
encryption/version/checksum policy and disposable account/character are required.
The accepted local development-auth path remains the fallback.
