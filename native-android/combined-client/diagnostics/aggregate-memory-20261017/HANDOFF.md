# Named memory ledger: world source owners and character dictionaries

This is receipt-bound arithmetic, not a measured integrated pipeline or device
memory result. `verify.py` checks nine exact committed receipts before reading
footprints. No native compiler, corpus, process, emulator or server is started.
Power-set import/index source is now independently reviewed; its footprint is
source-admitted here. Global child-budget composition remains unqualified.

The 96 MiB cap is 100,663,296 bytes. Existing A tests qualify two SOURCE meshes
and their shared owners plus historical TexOpt/Trick owners. They reserve the
actual common GEO loader once at 32 MiB and actual dictionary loader once at
16 MiB; these are configured reservations, not current resident bytes or RSS.
The source batch baseline includes explicit caller/provider/control allowances.
Do not erase those allowances or subtract unused loader capacity as free memory.

No row includes an authoritative actor, costume dictionary/actor resource owner,
initial-update packet, protocol retained loans, new Basic texture input owner,
material/composite namespace, Surface/GPU owners or driver allocations. A positive
number is an unassigned allowance, never proof that any such object fits. The
required buffer/lifetime composition for those objects is still unqualified.

There is also a harder API admission boundary: current standalone dictionaries
have 256 KiB, 1 MiB or 8 MiB complete named caps. Passing the full live world as
`retained_bytes` makes every such child refuse. Even dictionary-only import order
cannot silently solve this: category import with both origins requires at least
1,073,176 bytes above its 1 MiB cap; origin import with the category already live
requires at least 459,520 above its 256 KiB cap. These lower bounds include only
64 bytes of digest descriptor/expected hash and no external provider scratch.
A larger digest context can only increase them. Arithmetic coexistence alone
therefore cannot qualify the current APIs as one executable pipeline. A separately
qualified parent/global budget and explicit child partition/lease adapter is a
prerequisite. No cap is raised and no live bytes may be silently omitted.

Required lifetime/order constraints for that future integration:

1. Prepare raw dictionaries and copied projections before expensive world decode
   where possible. Track the complete global set throughout; retain strict child
   semantics until an explicit admitted adapter exists.
2. Retire each import workspace immediately after successful publication:
   class 463,208, category 374,856, origin 37,952, selected level 2,880 and pending
   sets 196,704 bytes. Workspaces are not retained owners and cannot be credited
   as free twice. Their own stack/digest/scratch remain transient phase charges.
3. Category and origin raw inputs may retire after copied imports. Class and set
   raw inputs must remain leased through every borrowed owner/span use. Category
   raw input 239,304 is not part of its copied owner's retained row above.
4. Retire named descriptors before their class owner and its raw input. If the
   application profile no longer needs a class family, retiring the normal
   family plus descriptor releases 1,682,556; retiring the villain releases
   4,691,352. Source normal/villain selection must be determined correctly;
   this ledger grants no permission to discard a required family.
5. Selected-level values are copied and can outlive source dictionaries, but no
   current compact replacement for all future named-table or class semantics is
   invented. Requiring later named lookup retains the full corresponding source.
6. Retire old texture/Trick owners before destroying their shared loader. Detached
   Trick by itself cannot release the old full-cache loader while TexOpt still
   pins it. A new separate Basic input loader adds another full reservation unless
   an actual same-loader owner/limits fixture qualifies sharing. Neither same
   asset path nor a matching cache hash is an ownership-deduplication permit.
7. Keep actual graph and GEO loaders alive until the final batch/mesh/Body lease
   is retired; mesh transfer does not retain those external dependencies. Release
   meshes/Body pins before loader destruction. Preserve cancellation/late-failure
   old and new owners together when computing replacement preparation peaks.

The immediate gates are a qualified parent/child budget adapter, explicit
selected-source retention policy, actual actor/packet/costume/resource sizes,
and a measured source-bound combined preparation/retirement sequence. Renderer
materials/current generation and authoritative world/actor publication remain
separate gates even if all named arithmetic fits.


## Qualified source geometry retirement changes the ledger

A separate c48e57126 source seal is now independently reviewed. It deep-copies
canonical geometry, all source records/headers/names/material labels, retains
actual Selection/join/catalog/snapshot and requires the external graph lease.
It stores no Body/index/loader/payload-stream pointer. The fixture actually trims
pins/cache, destroys the GEO loader and closes its provider before dereferencing
all new views. Merely consuming the old batch or reporting zero dependencies is
not enough to claim this release in an application.

This new baseline cannot be credited until a concrete application repeats actual
GEO pin/cache/loader/provider retirement while keeping the graph and all required
source owners alive. The allowance deliberately remains even though the host
fixture subsequently retires its old historical dictionary owners too.

Parent accounting metadata has an actual separate host footprint: 2,616 bytes
plus the 16,384-byte reserve =19,000, observed by existing calloc counters in the
cafaf853d output-only followup. Those bytes are added above; no overlap with the
older world's caller allowances is guessed. Actual module adapters will have
additional footprints not present in this table.

Consequently the required ordering for keeping both class families and sets is:
complete the seal transition, verify actual external GEO cleanup, then admit
additional retained sets/actor/resource owners. Already-retained C dictionaries
leave only 607,615 during that transition (588,615 after the measured parent),
so their temporary import workspace/provider/packet budgets cannot be ignored.
Alternatively retire unneeded dictionaries first according to their actual
source/lifetime requirements. A transition failure must keep old and candidate
charges, with no retirement credit until cleanup completes.

The post-retirement 33,302,065 allowance after measured parent is still unassigned:
it does not prove a costume/actor/packet/material/GPU workload fits, and it does
not close the small-cap all-retained API conflicts. The generic parent foundation
is independently source-qualified accounting only; concrete source-owned child
wrappers/actual lifetimes and one measured integrated preparation/retirement path
remain necessary. No further native execution or corpus/capture was used for this
ledger update.
