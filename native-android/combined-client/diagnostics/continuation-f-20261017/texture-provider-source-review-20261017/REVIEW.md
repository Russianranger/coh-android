# Texture namespace/provider boundary

This is an independent read-only source review at publication `6a6809d07a130af60129f569b59a627420b6bf54`. It proposes the minimum observable inputs for a future source-owned namespace descriptor. It does not implement or admit that descriptor, execute the original client, inspect authentic default texture bodies, or repeat a qualifier. The accompanying receipt binds the primary source files to their exact committed bytes.

The original startup path needs more than a flat list of `.texture` headers. A complete witness must close the selected namespace, its traversal and initial state, and the provider bytes actually opened while constructing each bind.

| Boundary | Source-backed inputs and behavior |
| --- | --- |
| Search roots and mode | `file.c:fileLoadDataDirs` resolves automatic discovery, explicit override, production/development state and ordered roots. It inserts roots in reverse order with `virtual_location = dirCount-1-i`, then adds PIGs. The source mode, exclusion/override bans and ignored prefixes affect the available tree. A descriptor can carry the resolved values with their actual producer identity; it must not replace them with an assumed root. |
| Filesystem candidates | `FolderCacheAddFolderToNode` consumes the actual directory entries, relative spelling, type, low file size and converted last-write timestamp. Root priority, directory exclusion and whether an entry was seen in the filesystem matter. Hidden/read-only/system attributes are stored by the cache, although `fileScanAllDataDirsHelper` projects only directory/normal type, size and timestamp into the texture scan callback. |
| Archive candidates | `FolderCacheAddPig` consumes each archive's identity and virtual location, then internal entry ordinal, relative name, timestamp, size and special-entry classification. Development mode can reject PIG-only entries. The original lock brackets entry enumeration and callback installation; an immutable provider descriptor needs a real equivalent byte/snapshot lifetime, rather than only copied filenames. |
| Path merge | `FolderNodeAdd` compares path components case-insensitively and preserves an existing node's spelling. Siblings are sorted by that comparison. Filesystem/filesystem collisions update when the new virtual location is greater than or equal to the old one. PIG/PIG collisions update when the new negative location is less than or equal to the old one. Mixed collisions prefer the PIG when its timestamp equals the filesystem timestamp or differs by the source's signed 3,600-second rule. A generic newest-file rule would change behavior. |
| Scan traversal | `FolderNodeRecurseEx` performs pre-order depth-first traversal of the sorted sibling tree. `fileScanAllDataDirs` has a separate absolute-path/no-cache fallback, mode push/pop behavior for quickload and good directories, dynamic tree loading, and a filesystem-seen filter in development-dynamic mode. A descriptor must identify the actual branch and scan request. Merely replaying OS enumeration or sorting complete paths independently is not a proof of this tree traversal. |
| Texture admission and basename state | `texLoadHeaderProcessor` prunes names beginning with `_`, accepts the case-insensitive `.texture` suffix, and can skip a basename already in the hash during later LWC stages. A cold-empty table must be an explicit source-established initial condition; later stages require the actual prior state. |
| Selected bytes and duplicates | `texFillInBind` performs a fresh `fileOpen(..., "rbR")`; `fileLocateRead_s` queries the cache again, and dynamic updates can alter the selected provider. The descriptor therefore must remain coherent through actual open/read. The embedded header path determines directory/name, not only the scan path. The basename hash keeps its first owner, while every successful bind is appended to `g_basicTextures`, including other directories sharing that basename. The duplicate timestamp check chooses a diagnostic filename and does not replace the hash owner. The separate ordered array and first-owner hash both need preservation. |

For an initial cold descriptor, the concrete minimum is the resolved source/mode/root/archive inventory and ordered candidate metadata; the exact case-preserving merged tree and scan branch; explicit LWC and initial basename-table state; and a pinned, immutable provider mapping from each selected tree entry to its exact texture/header bytes. Source-derived TexOpt/directory association and copied mip metadata remain additional construction inputs/owners. Dynamic callbacks, partial LWC inventory, or a provider change between scan and open need an actual source synchronization rule or a refusal.

This review identifies requirements, not a complete schema or algorithm proof. It does not infer a current namespace from historical retained duplicates or from the seven fixed header candidates. No memory subtraction, RSS reduction, startup improvement, global-budget admission, renderer generation, actor or world authority follows from these findings.
