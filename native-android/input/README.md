# Phase 10 bounded native input kernel

`coh_input.c` implements selected source input algorithms under an explicit Android adapter policy. It is a portable C11 library with no Windows, JNI, renderer, network, physics or entity dependency. `systems-probe` owns the Android event transport and JNI lifetime.

The immutable source pins in `../tools/input_fixture/source-pins.json` identify the original `Game/src/win/input.c`, `Game/src/graphics/camera.c` and UtilitiesLib math source/header. `check.py` compiles the unchanged bodies of `fixAngle`, `subAngle`, `addAngle`, editor `look` and `inpUpdateKeyEx`. Platform/UI callbacks are stubbed; source XY/Z/Rz joystick statements are separately extracted unchanged. This does not execute the full original client, command parser, bind dispatcher, camera matrix builder or gameplay camera.

The original editor `look` seam adds integer mouse deltas divided by 500, honors editor inversion, clamps mlook pitch to source ±90-degree limits, and produces the source target PYR after yaw +180 degrees and pitch negation. Non-mlook source pitch snap toward -2 degrees is also tested. The source `fixAngle` uses one conditional subtraction/addition, rather than a general modulo; the probe keeps frame deltas within ±500 integer units and initial PYR within the source angular domain. Source float operation order and the double-PI/F32 reciprocal RAD macro are retained. Builds require `-fno-fast-math -ffp-contract=off`.

Original DirectInput axes are scaled to integer -1000..1000 and compared strictly against -500 and +500. The adapter converts normalized Android axes with round-to-nearest (`lroundf`) to that integer domain. Exact normalized ±0.5 is neutral; the first active integer magnitude is 501. Key levels saturate at 127, and a press edge survives a same-frame release. Native release bits are an adapter diagnostic extension. Frame consumption clears edges and relative motion, while held levels remain. Focus loss, device loss and touch cancellation clear levels, edges, pending motion, active touch and axes. Camera orientation is retained across those transitions.

The Android preview policy maps the right stick through an explicit .15 dead zone to 2 radians per second, with valid frame duration 0..50 milliseconds. It carries no elapsed-time backlog, acceleration or smoothing state. The active stable touch pointer is normalized to -1..1 and converted into relative source integer deltas with scale 250. Per-frame delta saturation at ±500 is reported as `clipped`; malformed axes, coordinates, key IDs and frame times are rejected before native arithmetic and counted. These are Android preview decisions, rather than recovered original gameplay controller behavior.

InputAdapter uses Android source flags before interpreting events, standard X/Y and Z/Rz axes, HAT axes, and supported button KeyEvents. It consumes all historical samples for relative touch motion. Only the first controller is selected until disconnect; key/hat ownership is merged so an idle hat event cannot release an independently held D-pad key. Touch ownership is by stable pointer ID. External Android callbacks and in-app synthetic tests have separate counters. An emulator adb event establishes callback transport, not physical Thor controller operation. Standard mapping and source checks follow the [Android controller documentation](https://developer.android.com/games/sdk/game-controller/controller-input) and [MotionEvent API](https://developer.android.com/reference/android/view/MotionEvent).

The final UP coordinate is real movement input and contributes to the measured touch-direction mask, matching native END processing. It increments `touch_end`; `touch_move` remains limited to actual MOVE samples and their historical records. `adapter_check.py` compiles the actual adapter against bounded host transport stubs and verifies 43 checks, including four endpoint-only directions, zero displacement, an unowned pointer UP, historical MOVE accounting, source filtering and cancel. Removing only the final-UP accounting reproduces the +X failure as a negative control. These host checks are separate from real Android callback qualification.

The committed `input_goldens.h` contains 96 exact binary32 editor-look cases regenerated from the unchanged original source wrapper. `coh_input_selftest` compares all PYR/target components byte-for-byte and runs adapter state checks on the actual compiled native kernel. The independent host wrapper additionally compares 2,048 original key updates and 8,004 original integer axis cases with native output. The host command is:

```sh
python3 native-android/tools/input_fixture/check.py --output results/systems-probe/input-host-proof.json --sanitize
```

The source wrapper intentionally suppresses UI command side effects and matrix construction while retaining the selected scalar/key statements. Passing this gate does not qualify collision, character movement, the original camera obstruction/follow algorithm, gameplay bindings, user-editable mapping, input-to-photon latency or interactive frame-rate performance.
