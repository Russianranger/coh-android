# Real animation, hierarchy and attachment provenance

This probe uses the real source assets `huge/skel_ready.anim` (6,171 bytes, SHA256 `19edb695bb8ca18ea492ac556a68809e7eaebe40fe8d0bf550b7902f78f604e6`) and `huge/run.anim` (5,331 bytes, SHA256 `3a365aaabf6d67df5dc0aa5473a50585b8c64e6f2caa95d69dad0c0990afb1e6`). Both are acquired from the published `coh-assets-v1.0.0` Reference volume, inside `payloads/atlas/atlas-assets.zip`. Complete source-file hashes match the independently downloaded, SHA-verified `atlas-assets-index.tsv`. Large outer/inner ZIP hashes remain release-declared; they were not fully downloaded.

A fresh acquisition downloaded only 227,744 bytes in four exact HTTP206 ranges. The retrieval script enforces stable ETags, bounded ZIP member inflation, source size, CRC32 and complete-file SHA256 pins. It does not download a full PIGG or reconstruct keys from fabricated motion.

The source chain is specific to the selected Wretch-compatible geometry. `V_Arachnos_Wretch` selects `player.txt`, sequencer type `huge`; that type declares base skeleton `huge\skel_ready` and parent type `male`. `player/motion.inc` explicitly maps `RunCycle` type `huge` to `huge\run`, authored interval `[1,25]`. Those frame values are parsed literally. `MoveRate 0.7`, MoveScale and SmoothSprint are source sequencer behavior; the diagnostic clock does not reinterpret 0.7 as a wall-time multiplier. The probe exposes frame-unit playback over `[1,25]` at a declared diagnostic 30 ticks/second and rate 1.

The original base file contains a 100-slot BoneHierarchy with 60 reachable bones and 60 key tracks. The motion file contains 44 tracks and links back to `huge/Skel_ready`. All rotation tracks in these selected files use the original linear five-byte quaternion encoding; positions use six-byte signed coordinates or three float32 values. The native runtime receives the original encoded keys, not prebaked animation palettes.

The real mesh palette is global IDs `[9,5,7]`. Its parent chain is `9 -> 7 -> 5 -> 2 -> 1 -> 0`. The source Sleeves body part attaches through global ID 72 (`BONEID_SLEEVES`), with chain `72 -> 2 -> 1 -> 0`; it is not a fabricated connection to a convenient arm bone. Bone 72 has a real base key and is absent from the motion track, requiring the original base-first-key fallback. Both outer hierarchy roots, 0 and 61, are retained in the source files. Native and independent reference validation must account for the source's HIPS-root bind-position rules for unrelated roots.

`rig.bin` is a bounded COHRIG01 container: 128-byte header, unchanged base bytes, unchanged motion bytes, then three global palette U32 IDs. It records literal first frame 1, last frame 25, diagnostic tick rate 30 and socket ID 72. File-relative offsets are read bytewise; no Win32 pointer slot is cast to an ARM64 address.

Independent reference preparation compiles the pinned original local key decode/interpolation functions as a separate host oracle. A separate Python implementation builds hierarchy transforms, base translations, skin offsets, socket-relative palette rows and mesh position/normal goldens from those source-local samples. Six checkpoints include fractional frames and the last frame. The Android application must evaluate the encoded tracks at runtime; the references are validation checkpoints, not its animation driver.

The material and mesh continue to use the accepted Phase 6 GEO default material, including authentic gray fallback. This is not a recreation of the NPC costume override or the complete entity. Entity geometry scale 1.3, skinny/fat bone morphing, full movement-driven sequencing, transitions, effects, world placement and a complete character assembly remain outside this scoped probe. The shader reference is source-semantic scalar arithmetic; original Cg execution and original GPU texture capture are not claimed.
