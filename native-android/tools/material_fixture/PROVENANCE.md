# Real skinned fixture and material provenance

The probe uses `GEO_Sleeves_Wretch`, model zero from the genuine version 3 `data/player_library/v_arachnos_wretch_sleeves.geo`. The complete 6,072-byte source file SHA256 is `7d56d6fe65a1be2d02fe66e078b4c7b6a3998177dce47e8ac35b34a77baa413c`. It contains 116 vertices, 198 triangles, and three local palette bones mapped to global IDs 9, 5 and 7. Thirty-seven vertices contain a nontrivial blend between two distinct actual palette slots; their weights and indices are extracted from the original streams.

The primary texture comes from the selected model's actual TexID/name table: `Sleeves_Wretch_Base.tga`, resolving to `data/texture_library/v_enemies/arachnos/henchmen/sleeves_wretch_base.texture`. It is a genuine 256x256 DXT5 texture with nine mips. The secondary is the original `grey_tex` asset used by the default generic layer binding, recovered as `assets/texture_library/world/filler/grey.texture`; it contains an 8x8 ARGB8888 DDS with four mips and opaque gray pixels `(128,128,128,255)`.

This is the GEO default material. The recorded Arachnos NPC costume overrides the primary with `Sleeves_Skin_Wretch_Base` and resolves `none` on its secondary to `white_tex`. Those costume overrides and the full NPC entity are outside this probe. The default generic-layer fallback and source `grey` texture lookup are recorded in `pins.json`; they must not be described as the NPC costume's material pair.

The geometry and primary texture are selectively acquired from `coh-assets-v1.0.0/COH-Assets-1.0.0-Base.zip` -> `payloads/runtime/client-visual-assets.zip`. Each complete source SHA256 matches the published child manifest, independently downloaded and verified against `8587015400e1af639e2118649f0d9c77a089d564bfe2c97cbf9d80baaee5f9a2`.

The genuine gray texture is acquired from `COH-Assets-1.0.0-Reference.zip` -> `payloads/atlas/atlas-assets.zip`. Its SHA256 `b628966e91a864f9edcb0634605823a7ef3d8e2305f36d1a9f6e9834b018a013` matches the independently downloaded, SHA-verified `atlas-assets-index.tsv` (`1df633c5dc22667861380824f09eb6d98463a0ae025fd756b1e15ca29b933480`). Complete outer and inner ZIP hashes remain release-declared; the large archives were not fully downloaded. The acquisition tool enforces exact HTTP206 ranges, stable ETags, ZIP CRC32 and complete source-file SHA256 pins.

The independent Python reader decodes original zlib and component-delta streams bytewise, resolves a bounded 72-byte BoneInfo record, and converts the original per-vertex U8 weights and two U8 matrix row offsets. Weights follow the source expression `weight_byte * 1.f / 255.f` with float32 division, then `weight1 = 1.f - weight0`. Matrix row offsets are divided by three to obtain local palette slots. Canonical UVs include the original `modelFixup` float32 `V = 1.f - V` applied before GPU upload, with unit material bind scales for this scoped fixture. Native mesh parsing and source-function oracle checks are separate qualification steps.

`mesh.bin` is a canonical COHMESH1 record: 64-byte header, 48-byte vertices (position3, normal3, UV2, weight2 float32 and two local bone U32 IDs), triangle U32 indices and palette global U32 IDs. `poses.bin` has a 64-byte COHPOSE1 header and two palette/golden records. The identity palette and controlled rotations/translations exercise the stock shader's two-bone lerp and post-blend normal normalization; they do not claim reconstructed original animation or a recovered original bind pose.

The primary material uses the existing generic BC decoder with alpha preservation, which matches the GPU upload role. The genuine gray texture uses a narrowly bounded offline ARGB8888 BGRA-to-RGBA conversion. General uncompressed DDS support in the native core remains a separate gate. The probe uploads these real converted RGBA assets; original hardware compressed-texture decoding is not claimed.

The five native assets are `mesh.bin`, `poses.bin`, `texture0.rgba`, `texture1.rgba`, and `material-reference.bin`. Their hashes and source links are recorded in `material-fixture.json`. Shader, fog, tint, alpha-test and source-over reference cases are generated by the separate stock shader contract oracle. Controlled validation parameters are distinct from full client lighting, costume and scene state.

The shader oracle identifies its output as `source-semantic-scalar`; it did not execute the original Cg compiler/program or capture the original GPU driver texture output. Four explicitly controlled 1x1 diagnostic secondary-map swatch cases supplement fourteen cases using the real material pair. The diagnostic swatch is not represented as a game asset.
