WHAT THIS REPAIRS

The latest recovered report passed the former receipt gate, prepared its
persistent profile, and started PostgreSQL, Wine and the ODBC driver. It then
failed with "Animation runtime/native identity differs" while preparing server
data, before DbServer, MapServer or the game client launched. Its retained guest
interval was 388.877 seconds (about 6m29s), including 250.224 seconds building a
cold server data mirror. Cleanup completed, including PostgreSQL shutdown and
owned Wine process cleanup. The outer recovery archive remains explicitly
interrupted/unverified; it does not verify attribution to the interrupted app
session, a completed save, or an Android kill or GPU crash.

The animation pack was pinned to its original MapServer producer. The newer
monorail MapServer retains the same animation reader, but its binary hash differs.
This repair permits that one exact, source-verified consumer while preserving
the original asset identity, complete animation byte checks, and rejection of
unknown or modified binaries. Both Atlas and Kings Row installation paths pass
the authenticated native package to the compatibility check.

Only those two guest helpers and their enclosing runtime manifests change.
The accepted Game, native server binaries, Android DEX/resources, GPU stack and
all four Assets 1.0.0 volumes remain unchanged. The .29 receipt repair is retained.
This is not an FPS or startup-speed optimization. The accepted .25/.26 runtime
behavior remains the compatibility baseline. The new dedicated host gate must
validate the actual published asset volumes with the actual candidate runtime;
publication and a public-byte audit are separate required gates. Neither proves
physical Thor startup, gameplay, Kings Row travel or save/reopen.

EXISTING INSTALLATION -- PREFERRED REPAIR PATH

1. Install .30 over the existing app. Do not uninstall, clear app data or
   reimport already verified Assets 1.0.0. Keep the existing character and
   completed imports. Uninstalling deletes private character saves/imports;
   diagnostic ZIPs are not a restore backup.
2. If evidence from the failed attempt is still needed, use Recover interrupted
   reports and export the retained archive before starting another test.
3. Run "Set up / update runtime" ONCE and wait for Runtime ready. This installs
   the two repaired guest helpers and enclosing manifests. The app may retain
   the old runtime generation until reviewed cleanup. Merely installing the APK is not
   the runtime refresh.
4. If a saved THORHERO exists, use "2 · Reopen saved THORHERO". If the previous
   attempt failed before character creation, choose "Create fresh THORHERO" when the
   app offers it. Do not clear preserved profile data to force creation.
5. First verify that startup passes the former animation compatibility failure
   and reaches login/world. Use COHLOCAL / offline; on the fresh-creation path create
   THORHERO. Record elapsed time and the last visible stage if it fails.
   This repair addresses validation, not preparation time: the latest report
   spent 250.224 seconds building a cold server data mirror before the failure.
   Another several-minute preparation is not itself evidence of a stall. Keep
   the app foreground, watch its stage/progress and capture the exact next
   failure. No startup-latency improvement is claimed.
   If startup fails, use Abort operation as available and export immediately;
   do not repeat asset imports as a troubleshooting step.
6. Once in the world, verify basic movement and camera. Release all controls for
   the ordinary 60-second neutral wait, choose "Save character / log out", wait
   for "Saved character verified", then "Finish and save report". Export the
   complete report. Reopen and verify the saved map and position before the
   separate monorail test below.

STORAGE

The four downloaded ZIPs total 4,786,819,808 bytes (about 4.46 GiB), unchanged
from .28. For a clean installation with downloads retained, plan 25-30 GiB free
INTERNAL storage. This is conservative planning headroom, not a measured Thor
installed footprint. Private imports, expanded resources, rootfs/Wine, caches,
reports and runtime generations require more than the download size. New zone/
audio archives and their decoded files alone account for about 5.815 GiB.

Import admission requires approximately 3.654 GiB free (twice the largest
volume payload plus 512 MiB); setup checks for 5 GiB free at entry. These are
admission checks, not total-size guarantees. An existing .28/.29 installation does
not need to download/import another asset copy for .30, but runtime refresh
still needs working space. SD storage can hold downloads; private runtime data
still needs internal storage. With no session running, use Storage and cleanup
to scan and review older generations. Do not delete character data manually.

MONORAIL TEST -- AFTER STARTUP AND SAVE/REOPEN PASS

1. Keep "GPU test", the accepted Performance/800x600 selection, visual settings,
   fan and charging state. Enable Show FPS and 30 FPS. The retained Performance
   preset already uses a 600x450 world within an 800x600 interface; .30 adds no
   resolution, draw-distance or visual-feature reduction.
2. Reopen THORHERO, walk to the real Atlas Park monorail entrance, click it and
   choose Kings Row. Preparation is automatic. Stay near the station and in
   the app until arrival; walking away can invalidate the request.
3. Record station-selection-to-usable-world time, FPS range/dips, temperature,
   errors and visible artifacts. First preparation, later validated cache reuse
   and a server already resident in the session are different cases. None by
   itself proves a cold Android filesystem cache. Host times are not Thor times.
4. In Kings Row check walking, Jump, camera, clicking, buildings, terrain,
   textures, NPCs and audio. Return through its monorail station to Atlas Park.
   If stuck or unusable, abort and export early; do not run an immobile benchmark.
5. Neutral wait -> Save character / log out -> Saved character verified ->
   Finish and save report -> export -> reopen and confirm map and position.
   In another focused session, save normally in Kings Row and reopen there.
6. If an older save starts in Atlas instance 101, use its return control, then
   save, finish and reopen before Kings Row. Finish/reopen after safe-ground
   recovery before zoning. There are at most two resident MapServers and four
   transfer epochs in a finite 20-minute connected window with save time
   reserved. If too little transfer time remains, save, finish and reopen.

COMPLETE REPORT AND STORAGE EXPORT

1. Normally save, wait for Saved character verified, then Finish and save report.
   On failure, Abort operation early and preserve the failed report.
2. Select "Reports / export", then the matching UTC timestamp/type/size in
   "Retained reports · newest first". In Android's Create document picker,
   choose Downloads or an SD destination, Save, and wait for "Report exported".
3. Attach the COMPLETE OUTER coh-atlas-gameplay-YYYYMMDD-HHMMSS.zip, including a
   failure report. An inner guest ZIP or screenshots alone omit evidence. Add
   your timing/FPS/temperature notes and the last visible stage/error.
4. "Export incomplete" retains the private report. Select it again and retry;
   the previous destination may contain only a partial copy. Exports are bounded
   to 512 MiB per report and a five-minute copy. After copying visibly begins,
   switching apps and returning is an optional foreground-export check.
5. After an interruption, reopen and choose "Recover interrupted reports"
   BEFORE a new test, then export the retained interrupted archive. Say whether
   Saved character verified appeared. Recovery does not certify an incomplete
   test or reconstruct missing evidence. Do not deliberately kill an unsaved run.
6. With the session finished, open "Storage and cleanup", run its scan and
   choose "Export storage report". For import/setup/storage trouble attach the
   resulting coh-storage-*.json alongside the outer gameplay ZIP. Review any
   proposed cleanup before selecting it.

KNOWN LIMITS AND PENDING DEVICE GATES

Only the Atlas Park-Kings Row station pair is enabled. The 66-map/72-archive
inventory audit does not make every zone playable. Six map source graphs retain
documented authored gaps; original FX/appearance and audio-reference gaps remain.
Audio container validation does not prove physical playback.

The retained receipt repair and exact animation compatibility checks, including
preflight of real published assets, are host gates. A pass does not establish a
successful full runtime boot on Thor.
Physical .30 startup recovery, both monorail directions, Kings Row save/reopen,
controls, visual/audio correctness, storage/export reliability, loading time,
peak memory and sustained 30 FPS remain device test gates. Keep the working
renderer and strict save checks; no long Software comparison is requested.
