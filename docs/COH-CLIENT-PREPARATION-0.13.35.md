# Client preparation changes for 0.13.35

The physical 0.13.34 report showed 54.7 seconds checking existing visual assets, 86.7 seconds checking existing all-zone assets, 8.5 seconds checking existing audio, 14.3 seconds validating client animation storage, 38.2 seconds walking texture headers, and 56.3 seconds initializing an isolated Wine GPU probe. These are measured prior-version phases, not promised savings.

This continuation changes six guest helpers:

- `atlas_world_assets.resolve_targets()` builds each parent directory's case-aware catalog once per pass. It rechecks directory identity, mode, owner, mtime and ctime after resolution. Every leaf still receives its existing complete readonly fingerprint and byte verification when required; linked or ambiguous directories fail.
- Visual and all-zone/audio proof receipts can rebind to a new runtime generation only after this process authenticates both current archive and manifest to exact pins, all installed output fingerprints match their previous byte proof, and the payload/root identity agrees. Wrapper metadata alone no longer forces hashing all unchanged original output bytes. Missing, rewritten, writable, foreign or unproved inputs retain conservative verification/failure behavior.
- Texture indexing uses the existing bounded per-invocation input resolver. Fresh metadata is still collected for all 38,986 physical-run texture inputs. The inventory representation, ctime checks, pack bytes and native fallback contract are unchanged. Shared parent resolution is reused only within the current scan, with a final parent recheck.
- Client animation binding recognizes exact absolute links to already checked original parents. Noncanonical links retain strict resolution. Original file size, timestamp, readonly state, owner, complete inventory, native consumer and Pig byte proofs remain required. Parent replacement during verification is now rejected explicitly.
- The GPU prerequisite path can retain its separately initialized probe Wine prefix after complete private-token cleanup and an independent native prefix lock/socket check. A nonblocking owned lock and durable busy marker precede every checkout. The identity includes the authenticated Wine/FEX runtime lock, exact GPU producer, actual Wine/wineserver command hashes, kernel identity and FEX root. Every closed prefix entry is rechecked without traversing Wine drive/DLL links. Unknown, changed, busy or live prefixes are preserved; a new generation or ordinary ephemeral prefix is used. Retained generations are bounded to eight.

**Both native Vulkan and current WGL/presented-pixel probes still run for every GPU attempt.** The reusable object is Wine initialization state, never a previous hardware success result. Only a successful current probe, exited leader, closed output streams, complete owned-worker cleanup and an independently stopped native prefix can publish a closed generation. Game/server Wine prefixes, character data and installed GPU/FEX/Wine payloads are untouched.

The first 0.13.35 probe has no prior prefix cache and still initializes one. Reuse benefit must be measured on a subsequent safe reopen. Ordinary probe failure preserves the existing pre-launch Software fallback; cancellation or uncertain process cleanup remains fatal.

## Host qualification

Six focused suites executed **186 tests, zero failures/errors/skips**. This includes 25 added regressions plus revised texture tests that verify fresh leaf coverage and ancestor replacement without requiring the deliberately removed repeated `Path.resolve()` calls. Cases cover source generation rebind, missing authentication, rewritten leaves with restored mtime, case conflicts, directory mutations, exact texture/native pack compatibility, original animation integrity, initialized GPU prefix reuse, current probe failure, busy/live/changed prefixes, lock contention, identity changes, cancellation, bounds and symlink preservation. Replacement before native launch or during cache finalization releases the lease, preserves unknown files and cannot claim safe cleanup. Optional publication I/O failure preserves a prefix only after rechecking ownership and independently stopped native status. A separate 68-test beacon, worktree and GPU-package host regression run passed; its initial invocation lacked the required import path and was corrected.

The exact working file hashes and command are recorded in `android-evidence/client-preparation-0.13.35-host-tests.json`. These fixtures are host validation; they do not fabricate native GPU results or replace full integration/publication qualification.

A separate 4,000-leaf host fixture compared the original 0.13.34 functions with the changed functions on exactly the same tree. Target resolution fell from 16,715 metadata calls to 210 (98.7% fewer). Texture inventory fell from 52,318 to 12,728 calls (75.7% fewer), with identical records and inventory digest. The one paired instrumented host sample took 0.126→0.092 seconds for target resolution and **0.212→0.241 seconds for texture inventory**: host texture wall time did not improve. The intended reduction is filesystem crossing cost under Android/PRoot, which remains unmeasured. Full details and measurement limits are in `android-evidence/client-preparation-0.13.35-host-metadata.json`.

The cache keeps a bounded on-disk Wine prefix. It does not keep a native MapServer, Game, GPU probe or its RAM resident after cleanup. Temporary inventory memory is bounded by 16,384 entries; no device RSS/PSS improvement is claimed.

THORHERO remains saved in Kings Row. Measure cold and safely reused preparation separately on the next physical test, with explicit user capture controls and complete outer ZIP export. Under five minutes remains a device acceptance target, not a host-derived claim.
