Existing complete/fallback/interrupted reports, export retry, safe storage scan and owned cleanup retain current regression gates. Unknown enhancement loot/equip/combining changes remain diagnostic-incomplete with raw before/after evidence; this bounded comparison does not prove a native save failure and does not independently qualify those gameplay changes.

The .35 manual Start test / Stop test capture controls and unexpired saved-character gameplay remain unchanged. There is no user gameplay/countdown gate. ## Native critical path and dynamic maps

On-demand native MapServers and same-session resident reuse already exist. A cold destination still initializes definitions, sequencers, FX, physics and client world data. Changing the launcher alone cannot remove that work. Resident-map reuse is different from warm filesystem or closed provider-cache reuse. See [native research](COH-NATIVE-STARTUP-RESEARCH-0.13.36.md) for the separate observer candidate and required native qualification.

This guest stage targets avoidable GPU prefix initialization, repeated Atlas preparation, source metadata and collision revalidation. It does not eliminate the measured roughly 4–5 minute native Game/Map loading phases. The next native work needs measured BIN freshness/decode, sequencer and shader source/object/driver costs, exact provider-generation compatibility and conservative fallbacks. Full native world/graphics/collision parity is required before replacing shipping components.

## Qualification and physical gates

Current host qualification, strict disposable PostgreSQL tests, actual complete imported-assets cold/warm preparation for both destinations, authentic retained Windows minimal Db startup/restart, signed APK reconstruction and independent public-byte audit are mandatory. Historical donor/helper/native evidence keeps its original producer/source identities; no inherited test is labelled freshly executed.

At publication the exact outcomes and source pins will be recorded in HANDOFF and the publication receipt. Under-five-minute startup, under-one-minute client initialization and under-30-second zones remain false/unverified physical claims. No RAM/FPS/thermal improvement is asserted; parallel startup can increase transient pressure, and cache proof inventories remain bounded and released after durable destination proofs exist.
