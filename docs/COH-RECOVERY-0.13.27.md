# 0.13.27 — report recovery, automatic Atlas travel and preparation

This continuation preserves the user's accepted .25 performance baseline and
the two physically successful .26 transfers. The user reports that preparing
the destination severely reduced gameplay performance, while the transfer was
acceptable. The missing original session prevents a numerical comparison. The
later `coh-atlas-gameplay-20261011-003909.zip` is a failed reopen with a stale

## Changes

One **Travel** action requests destination preparation and then the ordinary
native transfer. The report records the initial tap, cold or already-running
destination, preparation, native arrival and three fresh destination views.
Preparation is included in total loading time. Backgrounding cancels pending
automatic dispatch; current session, character, map and epoch checks remain.
Atlas Park 1 and its instance 101 are the only enabled destinations.

Preparation scans only newly appended console bytes, retaining overlap for
split crash markers and the existing size/identity guards. Where the actual
kernel permits a verified reversible change, it temporarily adds five to the
Linux nice value of the destination's exactly owned threads. A disposable
process first proves permission to restore priority. Identity, inherited
priority and restoration are checked before readiness. Unsupported kernels
remain unchanged. Game and shared Wine processes are excluded. This is a
contention mitigation; it does not establish a shorter physical load time.

Bounded observations retain native stage history, destination CPU/RSS and
scheduling membership, plus optional system pressure counters. RSS is not PSS;
system pressure is not attributable to a single process. Phase wall time is not
pure GPU time. The original session deadline and neutral/save reserves remain
in force; a request without enough remaining time is refused.

Session, zoning, lifecycle and save metadata are atomically checkpointed, with
up to six selected captures. Recovery can package surviving evidence without
claiming a verified save or clean completion. Existing reports are retained and
the newest eight are selectable. Fixed guest evidence is preserved before a
retry can retire it. Report copying runs in the foreground service with bounded
streaming and a timeout; a failed external copy leaves the internal report.
If a provider ignores cancellation while opening a file, its single isolated
request can keep further exports unavailable until it returns or the app is
restarted; gameplay/service work is released. Bounded provider subsections are
rejected rather than written past their declared limits.

A stale display socket is removed only after private-directory, app UID,
socket type/link/inode, exact connection-refusal and repeated process-liveness
checks. Ambiguous state remains blocked. The conservative cleanup guard remains:
after a genuinely interrupted process, force-stop and reopen once if requested,
then use recovery before starting another session. No character/profile data is
deleted. Evidence already overwritten by .26 cannot be reconstructed.
