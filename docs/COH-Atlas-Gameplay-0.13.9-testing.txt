COH Atlas Gameplay 0.13.9 — exact NPC textures and lower-cost client preparation

Install over your existing app and run Set up runtime once. Keep the imported
assets, THORHERO, database, completed tasks and the same graphics preset.

This release preserves the exact 0.13.8 Game, its known-length string copy and
BIN open/CRC/freshness/decode instrumentation, the corrected Android acceptance
DEX, DbServer, MapServer, DLLs, graphics, generated-cache formats and animation
pack. It adds only six exact original NPC textures named by the existing
first-visit Atlas console. Every prior visual leaf remains unchanged, including
the 0.13.8 Hellion geometry and selected vegetation/LOD material repair.

Client console identity parsing searches the complete current console without
splitting every unrelated native log line. Late duplicates, invalid identities,
session/PID checks and retry boundaries are still checked on every observation.
New timing separates this parsing from native protocol/character observation.
Texture preparation computes shared paths once while retaining strict resolution
and readonly metadata checks for every leaf. Its report separates full inventory,
original-header reads and validation/publication. Native loading, LOD distances
and rendering are unchanged. Host CPU improvements do not establish Thor savings.

The six added textures require one texture-header index refresh. Record this
prelaunch preparation separately from actual Game startup. Existing generated
client caches and server/runtime reuse remain available.

Expected result
- Existing hero reaches Atlas; previous visible assets do not disappear.
- New NPC textures install or reuse successfully, and native client loading
  still reports exact verified assets. Appearance remains a visual check.
- White objects and hostile visibility are compared explicitly; unchanged
  defects remain open rather than being called fixed.
- Actual client startup does not regress materially versus your roughly 4:24
  0.13.7 measurement using the same preset. A faster result is needed to accept
  a physical startup improvement; one slower run alone does not isolate its cause.
- Cleanup finishes with zero owned workers. Intentional Abort/cancelled is
  expected for this visual/timing review and is not itself a failure.

Failure for this candidate: crash, inability to reach Atlas, loss of previously
visible assets, visual-package validation error, unclosed owned workers, or a
material repeatable startup regression. Report the stage and export its ZIP.
