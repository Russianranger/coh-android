# Prepared server caches and stable startup reuse

This change implements the user-selected startup research options **1, 2, 8 and 3**
on the existing `codex/character-persistence-continuation` branch. The retained
public donor is COH Atlas Gameplay 0.12.0. Main and draft PR #1 remain preserved.

| Option | Implemented behavior | Compatibility gate |
| --- | --- | --- |
| 1 | Prepare MapServer-specific powers, story, contact, dialogue and spawn Parse6 bins in disposable hosted data; seed missing private server bins. | Exact unchanged MapServer, accepted input/supplement/schema/identifier closure, bounded complete envelopes and genuine second-pass native consumption. |
| 2 | Refresh verified client wrapper receipts in place and rekey a proven closed server cache without moving its data roots; bind texture headers to stable content identity. | Native file hashes, import/cache/prerequisite identities, immutable roots, owned cleanup, directory/anchor/private-entry checks; ambiguous or changed inputs retain safe preparation. |
| 8 | Include English general, story and static server MessageStore bins, using their actual 20090521 format. | Exact source/locale/executable/identifier binding; bounded string tables, IDs, help/type indexes and native consumption; no client/server cache renaming. |
| 3 | Preserve trusted USTAR/PAX component modification times during Android extraction. | No metadata writes through symlinks; bounded representable dates; genuine Wine upgrades still consume readiness and require registration plus PE32 proof. |

The generator runs the shipped MapServer in an isolated source tree with no
player database. It uses the existing dictionary preload/TSR route and an owned
console Escape for ordinary completion. Timeouts and forced process termination
cannot qualify a donor. The second pass must read every selected bin, keep its
bytes unchanged and avoid rebuilding its cached definition/message sources.
Native completion, error output, file consumption and generation source pins
belong to the evidence artifact; inspecting a Parse6 header is not a native hit.

The guest verifies the donor before writes, never overwrites existing generated
bins, never seeds templates/attributes/DB-ID maps, and uses atomic no-replace file
publication compatible with PRoot. Missing or incompatible caches retain normal
native source-loading fallback. The donor's fixed compatibility policy enters the
server identity; wrapper version and archive transport hashes do not invalidate
otherwise qualified private cache contents.

The accepted physical 0.11.6 baseline was **21m50s from session start to Atlas
server readiness**, including **411.258s first-use server data staging**. Powers,
story and spawn stages together took **395.500s**, including runtime work that
caches cannot remove. The English message stages took **37.327s**, also including
work retained on a bin hit. These opportunities overlap existing warm cache reuse
and must not be added together as a promised device saving.

The first update from legacy extraction dates may still require one genuine Wine
registration. Android timestamp precision is provider-dependent; stable whole
INF seconds are the required property. Existing imports, character data and Wine
prefixes remain intact. The five-minute target includes all required preparation
and remains a future Thor measurement, not a qualification assertion.

Contact dialogue and normal saving without recovery remain physically pending.
The update preserves accepted client performance, F as Follow, optional recovery,
bounded contact capture, SQL identity/powers/costume protections and owned cleanup.
The accepted camera/jump/outdoor/recovery checks need no repetition. GPU work,
server lifetime changes, database durability changes and unrelated research
options are outside this update.
